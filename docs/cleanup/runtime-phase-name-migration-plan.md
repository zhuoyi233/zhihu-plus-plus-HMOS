## 1. 目标与边界

| 当前名称 | 目标名称 | 数据性质 | 处理方式 |
| --- | --- | --- | --- |
| `cacheDir/p4-images` | `cacheDir/picked-images` | 选图临时文件，以及已保存草稿引用的图片 | 新写入切换目录，旧文件校验后复制，保留旧目录读取能力 |
| `cacheDir/p4-share` | `cacheDir/share` | 分享临时文件 | 新产物使用新目录，旧文件按分享生命周期退出 |
| `probe:p1-production-opened-content` | `probe:production-opened-content` | 生产数据库中的诊断记录键 | 新探针使用新键，精确清理旧键残留 |

`picked-images` 同时涵盖未保存的选图和草稿引用，不暗示当前图片已经持久化到 `filesDir`。本轮保持草稿 JSON、加密信封、账号隔离和四模块结构；图片转入持久存储另行设计。

完成分成两个层次：

1. **业务切换完成**：正常业务只生成新名称；旧名称集中在迁移适配器及兼容测试中。
2. **兼容代码退役**：只有在产品明确不再支持从旧布局直接升级后，才能删除旧名称读取与清理代码。用户可能跳过中间版本，“发布过一个过渡版本”不能证明所有设备已经迁移。

源码注释中的 `P3-7`、`P4-2` 等历史任务编号、历史文档和编码数据不在本计划的运行时迁移范围内。

## 3. 通用安全约束

- 文件操作根目录只来自系统 `cacheDir`，子目录只接受表中的固定名称。文件名沿用受控格式；拒绝目录穿越、嵌套路径、非普通文件和会跳出根目录的链接。
- 复制、校验、最终文件就位和源文件删除分别记录结果。失败保留源文件，下次可以重复执行；不以“开始迁移”或“扫到空目录”标记永久完成。
- 使用进程内统一调度协调迁移、清理、保存、移除和上传；按文件名去重，避免多个页面同时复制或删除同一文件。
- 冲突文件不覆盖。只有确认新旧内容相同，才能把同名目标当作已经迁移；大小相同不足以证明内容相同。
- 限制每批文件数量、总字节数和并发数，后台分批执行；单个文件失败不能阻断启动或其他草稿的恢复。
- 诊断只记录数量、步骤和错误类别，不记录图片内容、账号、草稿标题、完整路径、原始 URI、密钥或会话。
- 保持 API 23 兼容。实施时核对所选文件、摘要和数据库 API 的最低版本，迁移本身不触发上传或发布。

## 4. 图片目录：先保护引用，再迁移

### 4.1 前置条件：统一图片所有权

1. 为图片维护“已保存草稿引用”和“当前编辑、上传、迁移占用”两类保护信息。保存成功后才更新持久引用；取消编辑、移除图片、删除草稿都需要重新判断是否仍有其他所有者。
2. 增加数据库维护层内部的引用收集接口，覆盖本机所有账号、回答与想法草稿，只向缓存维护器返回受控文件名集合。业务页面继续使用按账号查询接口，不增加跨账号草稿浏览能力。
3. 当前 `ContentDraftMetadataStore` 只有按账号枚举能力，不能只枚举已登录账号就清理共享缓存。数据库读取失败、引用 JSON 损坏或扫描不完整时，停止破坏性清理并保留待重试状态。
4. 普通 24 小时回收仅适用于没有草稿引用且没有使用者的临时文件；已保存草稿引用的图片不因创建时间久而被应用清理。检查生命周期状态转换中的删除决策，不能只修复目录扫描器。
5. 引用统计、保存落盘和删除检查使用同一个调度边界，防止扫描结束后新草稿引用了即将删除的文件。进程重启后先完成引用扫描，再开启清理。

这些规则保护应用自身的清理行为。图片仍在 `cacheDir`，系统回收缓存或用户清缓存后依然可能丢失；需要长期保存保证时，应单独把草稿图片移入持久存储。

### 4.2 统一路径解析与兼容范围

- 正常选图写入 `picked-images`；旧目录停止新写入。
- 将新旧目录常量、受控文件名校验和路径解析集中管理。旧字面量只留在专用迁移适配器，避免散落在平台实现和正则中。
- `LocalDraftImageReferences` 保持原序列化结构；从旧缓存对象提取引用时仍可接受严格受控的旧路径。
- 草稿恢复改为异步解析：先验证新目录候选，再处理旧目录候选。解析完成后才挂载持有图片的面板，避免初始空状态反向覆盖草稿引用。
- 迁移失败但旧文件有效时，允许使用经验证的旧路径。相应生命周期校验和上传读取器必须支持这个明确的兼容分支，不能让预览可读、上传却被旧正则拒绝。
- 若两处都缺失或冲突无法判定，保留原草稿引用并报告图片不可用；不能因为恢复失败而在下次保存时静默丢掉引用。

### 4.3 每个文件的迁移流程

1. 从已验证引用取得随机文件名，构造新旧两个候选路径；获得该文件的迁移占用，暂停对它的回收。
2. 通过文件描述符检查旧文件为普通文件，并验证大小、格式和图片尺寸与引用一致。源文件已经缺失时记录失败，不伪造空文件或重新访问 Photo Picker URI。
3. 若目标已存在：校验目标并比较完整内容摘要。新旧摘要一致即可复用；不一致时保留两份并报告冲突，不覆盖、不删除。目标损坏也不能直接覆盖有效旧文件。
4. 若目标不存在：复制到新目录中本次操作独占的临时文件。校验完整复制结果，比较源与副本摘要及必要的图片元数据，再将副本原子地转为最终文件；最终提交不得覆盖并发创建的目标。
5. 只有校验完成的最终文件可供预览和上传。草稿仍使用原 `fileName`；迁移不改动正文、账号键或远端图片信息。
6. 过渡期保留旧副本供失败恢复；结束保留期后，在没有旧路径使用者且新文件再次校验成功时逐项删除旧副本。不要对旧目录执行递归删除。
7. 任一步骤中断后，只清理确认属于本次操作且已无占用的临时文件。下次根据实际文件状态继续，不依赖一个全局完成标记跳过检查。

优先迁移用户正在打开的草稿，其余引用在后台分批处理。未引用的旧文件不必全部复制；只有引用扫描完整、无占用且已过原有生命周期时，才可回收。

### 4.4 失败与回退

| 场景 | 行为 |
| --- | --- |
| 磁盘不足、复制或校验失败 | 保留旧文件和草稿引用；旧文件有效则继续读取，稍后重试迁移 |
| 复制过程中进程退出 | 最终路径不暴露半文件；重启后检查临时文件与最终文件再重试 |
| 新目录有同名不同内容 | 保留两份，不合并、不覆盖；该图片不自动迁移 |
| 草稿元数据损坏、账号引用扫描不全 | 保留文件，暂停清理；其他可验证草稿仍可恢复 |
| 系统已经删除旧缓存 | 明确提示该图片不可用，保留其他正文和图片；不宣称迁移可以恢复丢失内容 |
| 发布后需要回退实现 | 回退包必须仍能读新旧目录，并停止源文件清理；不能直接回退到只认识 `p4-images` 的原始旧包 |

新写入已经使用新目录后，旧二进制无法读取这些新图片。即使保留旧副本，也不等于支持任意降级。若需要降级能力，必须另行实现并验证新到旧的导出流程。

## 5. 分享目录：新产物切换，旧产物按期退出

### 5.1 实施范围

1. 将 `SHARE_TEMPORARY_DIRECTORY` 改为 `share`，同步合同注释、测试夹具和所有实际文件生产者。实施时再次扫描生产调用；当前未发现生产者，不为改名新增导出或上传功能。
2. 默认分享载荷只接受新目录。确有旧文件任务时，由迁移适配器凭受控文件记录解析旧路径；不能把任意传入的 `p4-share` 路径直接加入公共白名单。
3. 已交给系统分享面板的旧 URI 保持原位，直到该文件不再被使用并满足清理条件。目录改名不通过搬走文件来打断接收方读取。
4. 分享文件没有草稿那样的持久引用需求，默认不批量复制旧目录；由受控清理器逐个回收过期文件。若实现前发现持久队列或可续传导出任务，需要先补充队列引用迁移再切换。

### 5.2 清理规则

- 保留合同中的时限：总寿命 24 小时，分享面板打开后的宽限期 30 分钟，清理时刻按现有 `min(创建时间 + 24 小时, 面板打开时间 + 30 分钟)` 计算；活跃使用者存在时仍延后删除。
- 当前生命周期辅助函数尚未接入生产清理。需要明确实际调度点、文件创建记录和使用者释放方式，并测试这些调用，不能仅修改纯函数后宣称旧目录已清空。
- 清理只枚举新旧专用目录内、符合已确认生产命名规则的普通文件。没有可信创建记录的旧孤立文件使用保守年龄判定；未来时间、未知名称、嵌套目录和链接保留待检查。
- 清理失败不影响文字或链接分享。旧目录为空时可以尝试删除空目录，失败留待重试。

过渡完成后可停止接收新的旧路径任务；旧目录的残留清理能力仍需覆盖直接从旧版本升级的设备。

## 6. 数据库探针键：更名并精确删除残留

1. 新探针只用 `probe:production-opened-content`，仍验证覆盖写、关闭重开、读取和删除。
2. 增加可重复执行的旧键清理：对 `opened_content.content_key` 使用完整旧键的相等匹配。旧键不存在视为成功；禁止 `LIKE 'probe:%'`、清表或删除真实浏览历史。
3. 在生产数据库已打开且表结构就绪后执行轻量维护。直接使用已打开的存储对象，避免维护逻辑再次调用 `AppDatabase.open()` 形成递归或死锁。
4. 探针开始前和结束清理阶段都处理新旧两个保留键；保持当前“清理失败也报告错误”的行为。数据库维护与探针执行共用互斥边界，防止维护器删掉正在验证的新探针记录。
5. 旧残留属于诊断数据，不需要改写成一条新记录。此次不变更表结构，默认不增加 schema 版本；若沿用已有维护版本机制，只有删除事务成功后才能标记完成，失败下次重试。
6. 后续版本继续保留精确旧键清理，直到不再支持从会写旧键的版本直接升级。

代码回退时应继续保留旧键清理能力。该操作只删除两个专用诊断键，不依赖用户是否再次手动打开数据库探针页面。

## 7. 实施拆分与完成条件

| 顺序 | 交付内容 | 放行条件 |
| --- | --- | --- |
| 1 | 收口图片引用、活动使用者与清理调度 | 已保存草稿超过 24 小时仍可恢复，多账号和删除竞争通过验证 |
| 2 | 探针键更名与残留清理 | 中断后残留可清除，真实历史不变，重复执行无副作用 |
| 3 | 分享目录切换与受控清理 | 新路径校验通过，旧 URI 在使用期间可读，过期文件按规则退出 |
| 4 | 图片目录解析、复制迁移和故障恢复 | 旧包创建的草稿覆盖升级后可恢复、可继续编辑；全部迁移失败用例有确定结果 |
| 5 | 收口散落旧名称，登记兼容入口 | 旧名称只存在于专用迁移代码、兼容测试和历史文档 |

步骤 2、3 可分别交付；步骤 4 必须等待步骤 1。每次代码 PR 都写明已覆盖的旧版本基线、实际验证和未完成项。

删除兼容适配器前，需要同时满足：产品已明确旧版本直升支持范围、范围内所有入口仍能完成迁移、跨版本测试覆盖跳过中间版本的升级路径。仅凭开发机旧目录为空或一次迁移成功，不得移除兼容读取。

## 8. 验证计划

以下均为后续实施必须完成的验证，本规划不表示这些用例已经通过。

### 8.1 自动化覆盖

| 范围 | 必测场景 |
| --- | --- |
| 图片路径 | 旧目录、新目录、两者并存、都缺失；非法名称、路径穿越、链接、非普通文件拒绝 |
| 图片完整性 | 同名同内容幂等复用；同名异内容保留冲突；截断、格式错误、尺寸不符不提交最终文件 |
| 图片中断 | 临时复制后、最终文件就位后、旧文件删除前分别中断；磁盘不足、权限错误、重复启动可重试 |
| 图片所有权 | 多账号、多草稿共享引用，保存与清理竞争，编辑取消、上传占用、迁移占用、超过 24 小时的已保存草稿 |
| 草稿数据 | 仅图片、空正文、混合本地与远端图片；迁移不改正文和账号范围，恢复失败不静默清空引用 |
| 分享 | 新目录接受，任意旧路径拒绝；受控旧任务可用；30 分钟/24 小时边界、活跃面板、取消与清理失败 |
| 探针 | 仅旧键、仅新键、两键并存、两键均无；中断与删除失败后重试，其他历史记录保持一致 |

测试应覆盖文件适配器和真实调用链。纯路径函数通过不能替代复制后恢复、系统 URI 读取或数据库实际删除验证。

### 8.2 构建与 API 23 升级验证

代码实施后按仓库顺序在 PowerShell 7 执行：

```powershell
pwsh -NoProfile -File scripts/verify-harmony.ps1 -SkipDependencyInstall -SkipBuild
pwsh -NoProfile -File scripts/verify-harmony.ps1 -SkipDependencyInstall
```

用例数量由脚本动态统计，不固定使用规划时的 698。保留实际测试报告及 HAP 的 target API 26、compatible API 23 校验结果。

在 `ZhihuPlus_API23`（`127.0.0.1:5555`）上：

1. 用同签名旧包建立可追溯夹具：单图、双图、仅图片草稿，超过 24 小时的图片，旧分享临时文件和探针残留；记录文件摘要、引用数量与普通历史记录基线。
2. 覆盖安装新包。升级验证中不得用卸载或清数据解决签名问题，否则旧布局证据消失；应准备签名一致的测试包重新建立基线。
3. 冷启动后打开旧草稿，核对标题、正文、图片数量和实际显示；新选图片落到新目录，保存后重启仍能恢复。
4. 切换账号、删除一个共享引用草稿、保持另一个编辑器或上传任务占用，确认清理不会误删文件。需要网络上传验证时使用明确的测试内容，不触发正式发布。
5. 在复制过程强制停止应用，再启动验证可重试；模拟缺失、冲突和写入失败，确认源文件和草稿引用保留。
6. 用受控测试入口检查文件分享及取消，验证接收方读取和旧目录清理；验证旧探针键消失、新探针可运行、普通历史不变。
7. 用能读取新旧目录的回退包验证恢复；另测从原始旧版本直接跨过过渡版本升级。测试结束记录未解决问题，不以清空数据作为通过依据。

## 10. 实施与验证记录（2026-09-29）

### 10.1 实施内容

- **探针键**：`DatabaseProbe` 生产探针改用 `probe:production-opened-content`；探针开始前与结束清理阶段
  均精确删除新旧两个键；新增 `removeLegacyProductionProbeKey` 挂在启动 `database-migration` 任务
  （数据库打开后执行，失败静默留待下次），不依赖用户打开探针页。
- **分享目录**：`SHARE_TEMPORARY_DIRECTORY` 改为 `share`，新增 `LEGACY_SHARE_TEMPORARY_DIRECTORY`
  常量供清理器使用；分享载荷校验不再接受旧目录路径；新增 `purgeExpiredShareTemporaryFiles`
  受控清理器（仅枚举新旧专用目录、仅删除符合命名规则的普通文件、24 小时保守年龄判定、旧目录清空后尝试移除）。
- **图片引用收口**：`ContentDraftStore` 新增维护层接口 `DraftImageReferenceScanSource`
  （`listAllImageRefsJsonForMaintenance`，跨账号仅返回引用文本）；新增 `DraftImageReferenceCollector`
  收敛全部草稿引用为受控文件名集合，数据库读取失败或引用 JSON 损坏（`isParsableLocalDraftImageReferences`
  判定）时标记扫描不完整并跳过本次破坏性清理；`purgeExpiredControlledImageCache` 支持
  `protectedFileNames`，与图片迁移共用进程内维护队列；面板内的无保护清理调用移除，清理统一移至启动
  `cache-maintenance` 延迟任务（先引用扫描，后清理）。
- **图片目录迁移**：`IMAGE_UPLOAD_TEMPORARY_DIRECTORY` 改为 `picked-images`，新写入只落新目录；
  新增 `resolveControlledImageTemporaryFile` 统一解析（新目录有效文件优先 → 旧目录校验 → 复制迁移：
  `.copying` 临时文件 + 尺寸/magic bytes 校验 + 逐字节内容比对 + 原子改名 + 不覆盖冲突目标；迁移失败
  回退旧路径），草稿恢复与上传输入（`createControlledImageUploadInput` 改异步）共用该解析；
  生命周期校验、引用路径提取（`LocalDraftImageReferences`）与上传 URI 白名单（`DefaultImageUploadRepository`）
  均按"新目录 + 过渡期旧目录"放宽。
- **遗留竞态修复（计划外发现）**：草稿恢复时面板先于草稿元数据加载挂载，引用晚到不会触发解析，
  导致旧版即存在的"带图草稿恢复后图片不显示"问题。`ImagePickerPanel.restoredLocalImageReferences`
  改为 `@Prop @Watch`，引用到达后重新触发异步解析，并按文件名键与代际计数去重、防止迟到结果覆盖。

### 10.5 兼容层退役（2026-09-29，用户决策）

同日实施完成后，用户明确决策"直接退役，现在退役技术债最小"，放弃过渡期。退役依据：
旧版本自身即存在 24h 无引用保护清理的缺陷，`p4-images` 中超过 24 小时的文件（含被草稿引用的）
在旧版本上已被回收，实际仍依赖旧目录的活动数据趋近于零；`p4-share` 从未有过生产写入者。

**移除内容**：

- 图片：`LEGACY_IMAGE_UPLOAD_TEMPORARY_DIRECTORY` 常量、旧目录路径构建器、复制迁移器
  （`.copying` 临时文件、逐字节比对、原子改名）、维护队列、生命周期/引用提取/上传 URI 的
  双目录接受分支；`resolveControlledImageTemporaryFile` 回归单目录校验。
- 探针：`LEGACY_PRODUCTION_PROBE_KEY` 常量、探针开始/结束的旧键删除、启动任务
  `removeLegacyProductionProbeKey` 调用。
- 分享：`LEGACY_SHARE_TEMPORARY_DIRECTORY` 常量与清理器的旧目录枚举、空目录移除。

**退役影响（如实记录）**：

- 从 ≤0.5.6 直升且升级前 24 小时内选过图的草稿：打开时图片显示"不可用"提示（正文保留、
  引用保留、可重新选图），不再有旧目录自动迁移兜底。
- 旧探针键残留（仅在旧版本探针中断时产生）不再自动清理。
- 迁移成功的过渡副本（如本模拟器上的验证草稿）自然成为新目录常规文件，不受影响。
