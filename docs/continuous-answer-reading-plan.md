# 同一问题下的回答连续阅读模式计划

制定日期：2026-10-24。源码核对基线：`1b572364`。

状态：**P0 原型、P2 数据状态层、P3 页面与入口、P4 第一组（阅读历史 + 跨模式段落锚点交接）与第二组（排序继承/沉浸阅读/离页调度）已完成（记录见 §8-§10，真实数据验证通过），P1 正式渲染单元抽离与 P4 其余项（朗读/沉浸/划线/重过滤）、P5 完整验收待实施。本次用户已确认范围为**同一问题的回答连续阅读**。保留现有详情页，增加一种可选择的阅读方式；参考图用于确定交互结构，视觉继续使用项目的主题、排版和鸿蒙组件。

## 1. 目标与范围

读完回答 A 后继续向上滑，直接看到回答 B 的作者和完整正文；一个屏幕可以同时出现 A 的结尾和 B 的开头。跨回答边界保持同一次滚动，不需要触底后再次过滑、松手切页或点击摘要。

- 首期支持同一问题下的回答，继承问题页的默认／最新排序。
- 保留现有单篇阅读模式及其上下／左右切换手势；升级后仍默认单篇，用户主动选择连续阅读。
- 回答正文完整展开，沿用当前图片、公式、引用、脚注、视频入口、链接卡片和划线渲染能力。
- 文章、想法、首页推荐流保持现有入口；混合问题推荐流不属于本计划。
- 图中的热评预览、听过人数不纳入首期。当前 `Answer` 模型没有对应完整数据，不为复刻截图添加虚构统计或逐答请求评论。

## 2. 页面与交互

### 2.1 结构

```text
┌──────────────────────────────────────┐
│ 返回    问题标题（固定）    写回答／更多 │
├──────────────────────────────────────┤
│ 作者 A · 简介                  关注  │
│ 赞同统计／认可徽章                    │
│                                      │
│ 回答 A 完整正文                       │
│ 图片、公式、引用、链接……              │
│ 发布时间／编辑时间／IP 属地           │
│ 赞同 · 反对 · 收藏 · 评论 · 更多       │
├────────── 浅色分隔带 ─────────────────┤
│ 作者 B · 简介                  关注  │
│ 赞同统计／认可徽章                    │
│ 回答 B 完整正文……                     │
│ ……                                   │
└──────────────────────────────────────┘
```

- **固定问题标题**：跨回答滚动时不切换为不同作者标题；点击标题进入问题页。长标题省略，大字号下优先保证返回与更多可用，写回答可收进更多菜单。
- **回答信息头**：头像、作者、简介、可用徽章和关注按钮；点击作者进入个人主页。首期分享放入逐答更多菜单，避免窄屏头部拥挤。
- **正文与日期**：复用现有阅读设置；开启“置顶回答日期”时移到该回答正文前，文末不重复显示。没有返回的数据不展示。
- **逐答操作栏**：放在每篇正文末尾，随内容滚动；赞同、反对、收藏、评论、更多绑定该回答。大字号允许两行布局，按钮触控区不随图标缩小。
- **回答分界**：以留白和浅色分隔带区分，深色下使用主题对应色；正文不套多层卡片边框。
- **长回答跳过**：沿用“下一个回答”按钮开关；连续模式下滚动定位下一答信息头。下一答未就绪时先加载，失败停留原位置并提供重试。
- **加载状态**：在尚未加载的回答位置显示作者摘要与加载占位，成功后原位展开；分页失败显示尾部重试，已读正文仍可浏览。
- **结束状态**：本问题当前排序没有更多可显示的回答时明确提示，不自动串入其他问题。过滤后的数量不冒充问题的全部回答数。

### 2.2 模式入口与导航

| 场景 | 计划行为 |
| --- | --- |
| 设置 | 在现有“外观与体验”的回答设置附近新增“回答阅读模式：单篇／连续”；与“回答切换手势”分开存储 |
| 详情内切换 | 更多菜单增加“切换到连续阅读／切换到单篇阅读”；同步保存偏好，保留当前回答和段落位置 |
| 从问题页点回答 | 继承问题 ID、排序、已加载列表、游标及所点回答；初始视口准确落在所点回答，之前已知回答可向上回看 |
| 从首页、搜索、历史、外链直达回答 | 先显示目标回答，再取得所属问题的回答列表；不等待扫描列表才显示目标正文 |
| 直达回答不在已加载列表中 | 目标回答作为本次起点，其后追加默认排序中的其他回答并去重；不宣称这些是它的服务端相邻项，也不无限翻页寻找它 |
| 返回 | 连续流只占原来的一个回答路由；跨回答滚动不压入新路由。返回仍回到原入口及原列表位置 |
| 评论／个人主页／视频返回 | 恢复原连续流会话和当前段落，不重新打开最初那篇回答 |
| 修改排序 | 首期沿用问题页排序入口；返回问题页选择排序后重新进入，避免阅读中静默重排 |

问题页种子包含目标回答时，先建立前后顺序再恢复锚点；进入后不再异步向视口上方补插未知回答。直达模式后续分页再次出现起点回答时只去重，不重新移动它。

## 4. 技术设计

### 4.1 单列表承载多个回答

新增连续阅读行模型，将每篇回答展开为：信息头 → 正文块 → 日期区 → 操作栏 → 分隔带。只创建一个 `List`／`Scroller`，避免回答卡片内部再嵌套独立纵向正文列表。

- 行身份使用 `answerId + rowKind + blockId`；正文块 ID、段落 pid、脚注编号、测量缓存、链接卡片回调均带回答作用域。
- 同一回答的脚注 `[1]` 只能跳向该回答的参考条目，返回点记录为该回答的段落锚点。
- 图片预览、视频播放、划线、双击正文等回调显式携带来源回答 ID，不在回调执行时临时读取一个可变化的全局 ID。
- 新数据源按范围追加／替换／删除行，保持已显示行的稳定 key；投票计数更新不重新生成全篇正文。
- 字号、主题、窗口宽度变化先记录视口锚点，再重新测量；不能套用旧尺寸缓存。
- 原单篇组件先接入抽出的渲染单元并完成回归，再接连续流，避免维护两份富文本实现。

### 4.2 列表、全文与预加载

分别维护“回答顺序和摘要”“逐答全文加载状态”“当前视口”三类状态。

1. 首先请求目标回答全文，复用已取得的目标详情时避免重复请求；校验其所属问题。
2. 使用问题页种子或问题回答列表建立序列；按 ID 去重并沿用过滤结果。
3. 下一答全文提前预取：初始仅准备下一答，后续按距离下一答信息头约两个屏高触发。阈值为原型初值，依实测调整。
4. 初始全文并发上限为 2（一个当前需要、一个预取）；每个工作槽使用独立的仓库／HTTP client。分页另用独立仓库，避免单飞冲突和互相取消。连续流不复用单篇正在使用的请求实例。
5. 快速滚动时优先可见回答，取消过时预取；相同回答共享进行中的请求。全文回包必须同时匹配会话代次、账号、问题和回答 ID。
6. 分页即使被过滤为空，也只能在单次触发预算内继续请求。建议初值最多自动追 3 页，仍无可见回答时提供“继续查找回答”，防止自动请求失控；到真实末页则结束。
7. 区分整流初始化失败、某篇全文失败、尾页失败。每处就地重试；已展示内容不因某个请求失败被清空。

全文状态至少包括 `idle / loading / ready / error / evicted`，错误原因另行区分登录失效、内容不可访问和临时网络失败。删除或不可访问的回答保留简短状态行，允许继续向下阅读；登录失效保留已显示内容并提供现有登录入口。

### 4.3 当前回答与互动隔离

- 活动回答由视口参考线落在哪个回答区段确定，参考线初值为有效视口上方约三分之一；边界增加小幅滞回，避免两个短回答之间来回抖动。处于未加载占位时不把它记为已阅读。
- 点击逐答按钮、正文双击、打开图片等操作，以事件来源回答为准；活动回答只用于公共菜单、跳下一答和当前阅读提示。
- 投票、收藏、错误和忙碌状态按回答 ID 隔离；关注状态按作者 ID 共享，同一作者的多篇回答同步刷新。
- 复用现有业务仓库和乐观更新／回滚规则，但回写必须校验目标 ID 与请求版本。后台旧请求不能覆盖新会话。
- 评论、收藏、划线和更多菜单打开时固定操作目标，并阻止背景误滚动；关闭后回到触发位置。整个页面只保留一套当前弹层宿主。
- 有未完成互动时，保留对应操作对象至完成；模式切换不得取消一个已提交的写入后重新发送，也不能丢失回滚结果。
- 屏蔽作者／关键词后重新过滤已加载摘要和全文。移除可见回答时先保存锚点，落到下一可显示回答，若无下一项则落到上一项；清理匹配的预取任务与全文缓存。

### 4.4 阅读位置、历史与账号生命周期

- 逐答位置继续使用 `ReaderPosition`，保存回答内的块索引、签名和块内比例；不把整个连续流的全局行号写入原格式。
- 连续流会话额外记录 `questionId / sortOrder / activeAnswerId / anchor / viewportOffset`。当前路由内保留已知顺序和分页状态；持久化只保存恢复所需 ID 与锚点，不保存 Cookie、正文或长期复用服务端游标。
- 暂离到评论／作者页或切后台时保存位置，恢复优先采用同会话锚点。冷启动按入口目标回答重新建流；不承诺重建历史某时刻的完整服务端排序。
- 模式切换沿用同一回答路由，按“实际正在阅读的回答 + 段落锚点”交接；恢复失败回到该回答开头，不跳到整个问题的第一答。
- 预加载完成不写历史。实际正文进入有效视口且成为活动回答后，短暂停留确认再写本地历史并按现有规则上报；建议初值 800ms，明确点击逐答操作可立即确认。每次会话按回答去重。
- 将历史记录能力从 `ContentDetailController.load()` 的自动副作用中抽出，保持原单篇模式的既有触发语义。
- 页面失活停止新预取并使迟到回包失效；账号切换／退出登录使会话代次失效，清理账号相关详情、互动和弹层状态，再按新会话重建。
- AppStorage 广播携带路由身份，仅活动宿主处理；嵌套打开另一个回答页后，旧页面不能修改新页面标题或保存新页面位置。

### 4.5 长时间浏览与内存

懒加载只减少渲染节点，不等于全文和图片缓存有界，需要单独管理缓存。

- 全文缓存建议先保留当前、前一答、后两答，最多 5 篇；同时给 HTML／块描述的体积设预算。具体字节预算在原型测量后确定。
- 焦点选区、打开弹层、正在朗读或执行互动的回答暂时固定；关闭／完成后重新进入淘汰流程。
- 远处回答释放全文和已解码图片／公式等重资源，保留轻量摘要、顺序和高度占位；回看接近占位前重新加载。
- 高度占位带排版版本，正文恢复或移除时保持当前可见锚点及屏幕内偏移；窗口／字号变更使旧高度失效。不能直接删除上方行导致画面跳动。
- 单篇超长回答按块懒加载，图片按原有尺寸信息预留空间，未获得尺寸时采用一致的估算规则；加载后通过锚点补偿维持阅读位置。
- 轻量序列也需记录增长量：原型测量长会话后决定是否分段保存；首期不为限制条目数而静默丢弃可回看的回答。
- 若淘汰后回看、字号重排或图片迟到仍产生明显跳动，留在实验阶段修复，不以全量常驻所有正文作为发布方案。

## 5. 现有功能兼容约定

| 功能 | 连续阅读下的行为 |
| --- | --- |
| 回答切换手势与灵敏度 | 不挂载旧的上下／左右过滑切答手势；设置中说明仅适用于单篇，原值保留 |
| 底部固定操作栏 | 由逐答文末操作栏承担；原自动隐藏／握姿布局仅作用于仍存在的悬浮控件，不再留空白占位 |
| 跳下一答按钮 | 沿用显示偏好和拖动避让，定位下一答头部；按钮点击不增加返回栈 |
| 字号、排版、段距、主题 | 与单篇共用，变化后保持锚点；强调色读 `resolvedThemeColor`，主按钮使用对应对比字色 |
| 双击、长按选词、划线 | 复用原动作和手势仲裁，但所有操作显式绑定事件来源回答；选区存在时暂停淘汰对应正文 |
| 阅读进度条 | 表示活动回答内的进度，拖动只定位该答；不把未加载的整个问题伪装成确定的总进度 |
| 沉浸阅读 | 延续现有入口及退出方式；隐藏公共浮层时仍保留回答边界，不破坏逐答操作归属 |
| 朗读 | 朗读启动时选定的回答；滚动到另一答不自动换朗读内容，不自动连播所有回答 |
| 分享、复制、导出等 | 逐答菜单作用于该答；公共菜单明确指向当前活动回答，不能一直指向最初打开的回答 |
| 电纸书翻页 | 翻动连续列表视口，可自然跨回答；移除旧“翻过边界即替换单篇”的回调 |
| 无障碍与大字号 | 按“作者—正文—操作”顺序访问；按钮标签含所属作者或回答上下文，模式切换后恢复焦点 |

最低兼容仍为 API 23。复用 HDS 或现有模糊兜底；不得引入 API 26 专属 `uiMaterial` import。共享组件继续遵守 ArkTS 显式类型、BuilderParam 直接调用和 AppStorage 状态通道约束。

### 8.3 实现事实与坑（对 P1–P4 的输入）

1. **`onDataChange` 对按值传参的嵌套 @Builder 不触发重渲染**（P0 实测：行数据更新后 bounds 不变）。需要行内容可见变化的场景必须走「delete+add」重建该行（`replaceRowAt`）。P3 的投票计数/状态行更新要么按此路径，要么让动态内容落在组件 `@State` 内部。
2. **沉浸式标题栏（含聊天不透明样式）都是覆盖层，页面内容不自动避让**（复确认 whats-new 页结论）。原型页控制栏加 ~80vp 顶部让位解决；P3 正式页沿用 `NativeContentDocument` 的 `contentStartOffset(topInsetVp)` 方案即可。
3. **淘汰时机与占位高度**：从未渲染过的回答没有实测高度，释放占位钳制 120vp，恢复时校正较大但被锚点补偿兜住。P2 应给未渲染回答按类型估计高度（长/短答分档），进一步压小恢复校正。
4. **程序化 scrollBy 补偿在用户手势进行中也会生效**——P0 未观察到打架（补偿量小、单次），P4 需要在手势/动量滚动期间合并或推迟补偿，避免与手指滚动叠加。
5. **帧间隔统计是 onDidScroll 回调节奏的代理指标**，不是真实 vsync 帧耗时；模拟器数值（p95 29~48ms）只能作同机相对基线，P5 真机需换 SmartPerf/hiTrace 复测。
6. 模拟器 fling 动量大（单次 swipe 惯性可达数千 px），自动化验证需小步采样，否则会跳过边界窗口。
7. 夹具公式端点有风控（无会话 Cookie 可能 302 到验证页），未登录时公式回退 TeX 文本属预期行为，不影响滚动结构验证。
