# 详情页排版优化建议

日期：2026-10-22

状态：第一阶段已实现并完成基础回归；第二、三阶段及正文候选参数继续评估。

## 1. 目标与范围

让详情页具有清楚的信息层级、稳定的阅读节奏，以及更舒适的正文留白。

本方案优先覆盖回答与文章详情页，包括主标题、作者信息、正文和底部操作栏。问题详情页可复用标题与信息分组规则，但需要独立检查问题描述、统计与回答列表的衔接。

初版判断来自代码调研，当时未连接设备。后续实现已在默认 API 23 模拟器上完成基础回归，实际改动、验证范围与待解决项见第 7、8 节。第 2 节保留修改前基线，第 3–6 节保留分阶段设计方案。

## 2. 修改前基线与依据

| 项目 | 当前实现 | 待改善的阅读体验 |
| --- | --- | --- |
| 阅读区域边距 | `page_padding` 为 12vp，正文列表使用该值 | 文字可能离屏幕边缘过近，长行缺少留白 |
| 正文字号与行高 | 默认 16fp / 30fp，行高约为字号的 1.875 倍 | 横向偏满、纵向偏松，段落内部与段落之间的节奏不够鲜明 |
| 内容块间距 | 默认 12vp，多数块共用列表间距 | 小标题、图片、引用和普通段落缺少不同的分组节奏 |
| 标题层级 | 详情主标题与正文小标题默认均为 20fp、加粗 | 页面主题与正文分节的视觉差异不足 |
| 信息头 | 标题、作者、统计、话题等基本以 10vp 间距顺序排列 | 信息容易表现为连续堆叠的字段，正文起点不够突出 |
| 作者区 | 40vp 头像，姓名 16fp、简介 12fp | 已具备基础层级，可重点调整其与标题、正文的距离 |
| 底部操作栏 | 两组悬浮玻璃胶囊，正文从下方穿过 | 需要实测文字经过胶囊时的可读性与末段避让 |

实现依据：

- `entry/src/main/resources/base/element/float.json`：字号、页面边距和通用间距。
- `entry/src/main/ets/pages/ReaderTypography.ets`：正文、标题与段间距的百分比换算。
- `entry/src/main/ets/pages/ContentDetailPages.ets`：信息头、作者行、日期页脚与操作栏。
- `entry/src/main/ets/pages/NativeContentDocument.ets`：正文列表、标题与引用块。
- `entry/src/main/ets/pages/AnswerTitleBar.ets`、`ArticleTitleBar.ets`：滚动折叠顶栏。

## 3. 建议方案

### 3.1 阅读区域与正文

先使用下表作为视觉试验参数。字体与行高按 fp 计，布局距离按 vp 计；数值均为默认字体缩放下的候选值。

| 参数 | 当前默认 | 建议试验值 |
| --- | --- | --- |
| 正文左右边距 | 12vp | 20vp；窄屏对比 16vp |
| 正文字号 | 16fp | 17fp |
| 正文行高 | 30fp | 29fp |
| 普通段落间距 | 12vp | 14vp |
| 主标题字号 | 20fp | 23–24fp |
| 主标题行高 | 未显式设置 | 32–34fp，随选定字号配套验证 |
| 正文小标题字号 | 20fp | 19–20fp |

扩大边距可以让阅读区域更集中；略增字号并收紧相对行高，再适当增加段间距，使同一段内的文字更连贯，段落之间更容易区分。

正文左右边距应使用详情阅读区域的独立参数，避免直接修改全局 `page_padding` 而影响首页、设置页或操作栏布局。标题、作者区与正文使用一致的左对齐线。平板和横屏的最大阅读宽度另做适配，不直接将手机参数扩展成超长行。

### 3.2 主标题与信息头

主标题完整换行，避免为了压缩首屏而截断问题标题。回答页保留点击标题进入问题详情的行为。

信息头按三个层次组织：

1. **主标题**：最大字号与明确字重，承担页面主题。
2. **作者信息**：头像、姓名和简介形成紧凑的一组。
3. **正文**：通过组间留白建立清楚的阅读起点。

建议标题到作者区留 16–20vp，作者区到正文留 20–24vp；作者姓名和简介继续保持较小间距。以上均指最终可见间距，实现时须扣除已有列表间距和信息头底部内边距，避免叠加。

统计信息采用次要文字样式，减少独立占行。文章话题与推荐背书可尝试移至文末，或降低首屏视觉权重；保持入口和信息可发现。发布时间继续尊重现有“置顶日期”设置，未置顶时保留文末日期及 IP 属地。

### 3.3 正文内容块

| 内容类型 | 建议规则 | 目的 |
| --- | --- | --- |
| 普通段落 | 统一正文样式与段间距 | 保持长文阅读的稳定性 |
| 小标题 | 段前距离大于段后距离；试验段前 24vp、段后 10–12vp | 将标题与后续内容归为一组 |
| 图片与图注 | 图片和图注靠近，图注与下一段拉开 | 明确图注归属 |
| 引用 | 使用更淡的竖线，保留缩进及嵌套层级 | 区分引用，同时降低装饰干扰 |
| 链接卡片、公式与参考文献 | 沿用各自内容结构，检查其与正文的间距 | 避免统一间距挤压特殊内容 |

这些距离指内容之间的最终距离，不能在已有 `List.space` 上直接重复追加。新增块间距规则也需要尊重用户的段间距设置，避免出现正文设置改变而标题留白固定不变的割裂感。

### 3.4 顶栏与底部操作栏

保留现有滚动折叠顶栏、双胶囊操作栏和智感握姿换位能力。第一轮不新增交互，重点检查布局变化后的协调性：

- 主标题高度变化后，折叠顶栏仍在正确时机出现，无跳动或重叠。
- 正文经过玻璃胶囊下方时，操作图标及文字仍清晰可辨。
- 最后一段与文末信息能够完整滚到操作栏上方。
- 大字体、窄窗口下按钮可点击，数量文本不挤压主要操作。
- 沉浸阅读继续使用现有窄作者行，并与新的正文留白协调。

## 4. 已有阅读设置的兼容

项目已有字号、行高和段间距自定义能力。候选值不能直接覆盖现有用户设置。

当前 `ReaderTypography.ets` 的默认换算为：

```text
字号 = 16 × 字号百分比 / 100
行高 = 字号 × 1.875 × 行高百分比 / 160
段间距 = 12 × 段间距百分比 / 100
```

因此，修改基线常量会影响所有保存过相应百分比的用户，即使设置值本身没有变化。建议分两步推进：

1. 首先调整独立阅读边距、主标题层级和信息分组，保留现有排版换算。
2. 在视觉试验中比较 17fp / 29fp / 14vp 组合；确认效果后，再明确新装默认值与存量用户迁移策略。已有用户应保留原有实际排版效果，不能仅以“百分比未修改”作为兼容依据。

上述候选值不是现有滑块一定能精确表达的组合，不能直接取整写入设置。方案落地需要验证预设或迁移方案与现有档位的兼容性。

相关背景见 [排版自定义迁移实现文档](upstream-typography-settings-implementation.md)；详情页已有阅读设置入口的记录见 [Issue #54：详情页阅读设置入口](issue-54-reader-appearance.md)。

## 5. 实施顺序

| 阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| 第一阶段：信息层级 | 独立正文边距、主标题字号、信息头分组与留白 | 同一篇内容前后对比，标题、作者、正文层次清楚 |
| 第二阶段：正文节奏 | 试验正文参数，细化标题、图片和引用的间距 | 长文扫读更清晰；确定设置兼容方案后再落地默认值 |
| 第三阶段：整体适配 | 折叠顶栏、操作栏、窄屏、大字体、深色模式与横屏 | 内容无裁切、遮挡，原有阅读交互可用 |

第一轮优先完成第一阶段，并用第二阶段的候选正文参数制作对比。首屏可见正文量应作为观察项，结合易读性一起判断，不能只追求放入更多文字。

- 默认以 `ZhihuPlus_API23` 为最低兼容线测试目标；连接后核对设备实际名称、系统版本与 connectKey。
- 对比样本包括长标题回答、普通长文、含图片和图注的文章、嵌套引用、行内与独立公式，以及问题详情页。
- 覆盖浅色、深色、默认字号、正文大字号、系统大字体和窄窗口。
- 每组前后截图保持内容、设备尺寸、主题、字号设置与阅读位置一致，分别记录首屏、正文中段和文末。

### 检查项

- [ ] 主标题完整显示，作者简介省略合理，徽章不被挤出。
- [ ] 标题、作者区、正文左侧对齐，留白无重复叠加。
- [ ] 小标题与下一段归属清晰，图片图注关系明确。
- [ ] 公式、图片、引用和链接卡片无裁切或异常溢出。
- [ ] 用户字号、行高、段间距设置仍有效，既有用户实际排版效果按兼容策略保留。
- [ ] 标题折叠、沉浸阅读、回答切换、阅读进度恢复与滚动条定位可用。
- [ ] 文末内容可以滚到操作栏上方，操作栏各按钮可点击。
- [ ] 新增强调色使用 `resolvedThemeColor`；不引入 API 26 专属 `uiMaterial` import。

## 8. 回归发现与后续工作

本轮完成信息层级与留白调整。以下现象尚未定位根因，本次不宣称已修复，也不能仅凭构建或单测通过判定视觉验收通过：

- **主题切换后的公式对比度**：回答从浅色切至深色后，部分公式仍显示深色笔画，在黑底下难以辨认；普通文字与新信息头配色正常。需单独检查公式颜色与组件重建链路。
- **字号切换后的局部更新**：回答从 100% 调至 150% 后，小标题和部分正文放大，但首个含行内加粗文字的段落未同步呈现相同比例。需检查原生正文块及行内渲染子组件的状态更新链路。

第二阶段继续评估正文候选参数、标题段前段后间距、图片图注与引用样式，以及设置兼容方案。第三阶段继续覆盖系统大字体、不同窄窗口、横屏和平板、嵌套引用与图片等样本，并完成回答横向切换预览、阅读进度恢复、滚动条拖动定位及文末避让的可靠设备验收。本轮未将这些项目记为全量通过。
