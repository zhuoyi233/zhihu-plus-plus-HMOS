# 全应用上游 UI 布局与 HarmonyOS 迁移可行性分析

> 文档范围：全应用产品页面，不局限于 P5
> Android Lite 上游基线：`ec77d309`
> HarmonyOS 对照基线：`3bcc6eb2`
> 目标平台：HarmonyOS API 26
> 分析日期：2026-08-26

## 1. 结论

全应用 UI 可以采用“上游信息架构和按钮位置语义不变、HarmonyOS 视觉和交互规范原生化”的方式迁移，不能按 Android Material 组件逐像素复制。

手机端应严格保留上游页面的：

- 顶层导航项顺序；
- 页面从上到下的信息顺序；
- 返回按钮在左、页面级操作在右的关系；
- 主操作、次操作和危险操作的相对位置；
- 详情底栏中投票在左、收藏/评论/更多在右且“更多”最靠右；
- 列表行正文在左、状态或行级操作在右；
- 创作页退出/返回在左、发布在右；
- 输入页的主要确认动作位于操作区右侧。

迁移时应改用 ArkUI `Navigation`/`NavDestination`、`List`、`Tabs`、系统 Symbol、系统弹窗、半模态和 Picker，并使用 HarmonyOS 的字体、颜色、安全区、动态字号和响应式规则。达到宽屏断点后可以分栏或把底部导航迁到侧边，但不能改变入口顺序和操作语义。

当前鸿蒙工程已经具备登录、首页 Feed、关注/热榜/日报、搜索、问题/回答/文章、用户、想法、评论、收藏、通知、历史、创作、视频和屏蔽等生产页面，功能骨架覆盖较广；主要差距不是“有没有页面”，而是全局导航、标题栏、分组列表、底栏、半模态和宽屏结构尚未统一。话题详情、独立通知时间线/邀请/私信、完整设置子树仍属于明确缺口。

## 2. 分析边界和判定方法

### 2.1 分析对象

上游以 `refs/remotes/upstream/master` 的固定提交 `ec77d309` 为准，重点检查：

- `ZhihuMain.kt` 和 `NavDestination.kt` 的顶层导航与路由；
- `ui/*Screen.kt` 的页面结构、标题栏、Tabs、列表、底栏和浮动操作；
- `ui/subscreens/*Screen.kt` 的设置页面；
- 登录 Activity/Pane、对话框、操作面板和媒体页面。

鸿蒙以提交 `3bcc6eb2` 为准，重点检查 `P1Destination.ets`、`P1Shell.ets` 和 `entry/src/main/ets/pages` 下的生产页面。`*Probe`、`TechnicalLabPage` 等诊断页面不属于产品 UI 对齐范围。

### 2.2 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现/需收敛 | 功能页面和数据链路已存在，主要工作是位置、组件和视觉层级对齐 |
| 部分实现 | 主路径存在，但上游的子页、Tabs、页面级操作或状态不完整 |
| 未实现 | 鸿蒙没有对应生产路由或页面 |
| 平台裁剪 | Android 专属或已明确排除，不在鸿蒙保留空入口 |

### 2.3 “位置一致”的三层规则

1. **手机端严格语义一致**：保持前后、上下、左右和主次操作关系，不因改用 ArkUI 改变用户肌肉记忆。
2. **组件原生化**：Material `TopAppBar`、`Scaffold`、`BottomSheet`、`DropdownMenu` 等只作为结构证据，不直接决定鸿蒙控件外观。
3. **响应式等价**：宽屏可以把“底部”语义迁移为“左侧导航”，或把“父页→子页”迁移为“左栏→右栏”，但原有顺序、选中态和返回语义必须保留。

## 3. 全局信息架构

### 3.1 上游顶层页面

上游 `MainTabPage` 有七个可配置顶层目的地：

| 顺序 | 上游页面 | 手机结构 | 鸿蒙现状 |
| ---: | --- | --- | --- |
| 1 | 首页 | 搜索/通知顶栏 + Feed + 创建 FAB + 底部导航 | 首页已实现；搜索、显示、刷新和频道入口仍以两排按钮呈现，无统一底部导航 |
| 2 | 关注 | “推荐/动态”Tabs + 横向 Pager + Feed | 已有关注 Feed，但缺双 Tab/Pager 结构 |
| 3 | 热榜 | 榜单列表 | 已实现 |
| 4 | 日报 | 日期标题栏 + 日期选择 +日报列表 | 日报列表与正文已实现；日期选择和标题栏操作需对齐 |
| 5 | 在线历史 | 标题栏 + 菜单 + 在线记录列表 | `ReadHistoryPage` 合并了本地/在线能力，入口结构与上游不同 |
| 6 | 我的收藏 | 收藏夹列表 | 已实现为二级路由，未成为可配置顶层页 |
| 7 | 账号 | 账号头部 + 快捷入口 + 分组设置 | 登录/设置功能已实现，账号页仍是简化设置入口 |

上游允许用户选择其中 3–5 个作为底部导航，并在再次点击当前项时回顶或刷新。鸿蒙根 `P1Shell` 当前只把首页作为根内容，其他频道从首页按钮进入，且根 `Navigation` 固定为 `NavigationMode.Stack`。这是全应用 UI 最大的结构性差距。

手机目标结构：

```text
┌──────────────────────────────┐
│ [搜索内容................] [通知] │  首页顶栏
├──────────────────────────────┤
│                              │
│          当前顶层页面           │
│                              │
│                         [创建] │
├──────────────────────────────┤
│ 首页   关注   热榜   日报   我的 │  可配置 3–5 项
└──────────────────────────────┘
```

### 3.2 全局导航规则

- 根页面使用 `Navigation`，业务详情使用强类型 `NavDestination`，页面正文不再重复自绘返回按钮；
- 顶层页之间切换不重复入栈，详情页才进入返回栈；
- 重新选择当前顶层页触发回顶，再次选择或按既定规则触发刷新；
- 登录、风控、图片预览和视频全屏页可隐藏标准标题栏，但必须保留左上返回/关闭语义；
- 半模态、对话框和软键盘打开时，返回键优先关闭最上层临时 UI；
- 切页、旋转和窗口缩放后保留每个顶层页的滚动位置、筛选项和加载状态。

## 5. 启动、登录与风控

### 5.1 上游布局

Android 登录首页顶部横排“手机号登录 / 扫码登录 / 备用网页登录”三种模式，当前模式为强调按钮，其他模式为描边按钮；所选 Pane 占据下方剩余空间。手机号页从上到下为标题、手机号、验证码/密码流程、错误提示和登录按钮；二维码页以二维码或扫描说明为视觉中心；网页登录和风控页使用完整 Web 内容区。

### 5.2 鸿蒙迁移

- 登录页首屏仍保持三模式同一位置，不把 Cookie/网页模式藏进设置深层；
- 三个入口在窄屏可用等宽 Tabs 或分段按钮，文字不足时允许两行，但顺序不变；
- `PhoneLoginPage` 的国家区号/手机号/验证码或密码按表单顺序排列，登录为底部主要按钮；
- 二维码中间展示，刷新/取消位于其下；扫描电脑端登录码独立页保留左上返回；
- `WebLoginPage`、`RiskControlWebPage` 使用移动 UA 和系统安全区，Web 内容不套多余卡片；
- 登录完成后回到原业务页并刷新，不额外插入成功页；
- Cookie 仅用于状态和网络层，UI、日志和截图中不得显示完整值。

当前 `LoginPage` 已承载账号状态和多个入口，但模式选择被拆成不同卡片/跳转。建议统一成上游三模式首屏，同时保留鸿蒙已经完成的会话验证与风险控制能力。

## 6. 首页与频道 Feed

### 6.1 首页

上游传统布局为：顶部搜索胶囊占左侧大部分宽度，通知在最右；Duo3 变体把账号头像放入 64dp 搜索容器右端。信息流在其下，创建 FAB 位于右下，底部是顶层导航。

鸿蒙应以稳定的传统结构为默认基线：

- 第一行只放搜索和通知，不再并列“显示”“刷新”三个同强调按钮；
- 刷新使用下拉刷新，必要时在加载失败状态显示正文内重试；
- “显示与阅读”移入账号/设置，不占首页一级位置；
- 关注、热榜、日报进入底部导航配置，不继续作为首页第二排按钮；
- Feed 卡保持“来源/类型 → 标题 → 摘要 → 作者/赞同/评论”，行级更多在右上；
- 创建 FAB 位于内容区右下，展开后操作顺序与上游保持“提问题 / 写回答 / 发想法”；未实现提问题时不留禁用空位。

### 6.2 关注、热榜与日报

- 关注页顶部固定“推荐 / 动态”双 Tab，下面使用 Pager；鸿蒙当前单一关注数据源只能算部分对齐；
- 热榜保持序号在左、标题为主文本、热度为次文本，整行打开，不能把“打开”变成重复的高强调按钮；
- 日报标题栏显示日期信息，日历选择在右；正文列表按日期分组，列表项图片在上游存在时保持右侧缩略图语义；
- 所有频道统一下拉刷新、加载更多、空态、登录态和错误态的垂直位置，避免每页自定义一套大按钮。

## 7. 搜索与发现

上游搜索标题栏从左到右是返回、占据主要宽度的搜索输入、筛选。输入框内部搜索图标在左，非空时清除在右。执行搜索后，结果类型 Tabs 紧贴标题栏；空查询时正文先显示搜索历史，再显示热搜；结果列表在其下。

鸿蒙 `SearchPage` 已有输入、清除、搜索和结果列表，但应调整为：

```text
┌──────────────────────────────┐
│ [返回] [搜索输入.......×] [筛选] │
├──────────────────────────────┤
│ [综合] [用户] [话题/其他结果类型] │
├──────────────────────────────┤
│ 历史 / 热搜 / 搜索结果             │
└──────────────────────────────┘
```

- 键盘搜索键和标题栏输入共同提交，不保留正文中独立的大“搜索”按钮；
- 搜索过滤使用右上系统菜单或半模态，选择后原地刷新；
- 历史标题右侧放清空菜单，热搜标题右侧放关闭/刷新，行级操作不挤入正文左侧；
- 结果行继续使用高亮标题、摘要、作者和统计；用户结果的关注按钮固定在行尾；
- “搜索 TA 的创作”仍从用户页右上进入，搜索页复用同一布局，只限制结果域。

## 8. 问题、回答、文章与日报正文

### 8.1 问题页

上游从上到下为：

1. 左返回、动态标题、右侧日志和分享；
2. 问题标题、浏览/评论/关注统计；
3. 问题描述与展开/收起；
4. 话题 Chips；
5. “写回答”和“关注问题”操作；
6. 默认/最新排序；
7. 回答列表。

HarmonyOS 应保留该纵向顺序。日志若仅为开发诊断则从生产 UI 裁剪，不留空位；分享继续在右上。`ContentDetailPages` 已有标题、正文、写回答和关注能力，但应把问题页与回答/文章页的标题栏和底栏结构分开，避免使用同一套通用卡片导致位置失真。

### 8.2 回答与文章

上游使用可折叠的双行标题栏：返回在左，标题/作者在中，页面操作在右；正文区依次为作者、标题/所属问题、正文、话题和补充信息。固定底栏的核心位置为：

```text
┌──────────────────────────────┐
│ [赞同/票数] [反对]   [收藏] [评论] [更多] │
└──────────────────────────────┘
```

鸿蒙现有底栏已基本满足上述位置。后续重点：

- “更多”固定为最右，不用文字按钮替代 Symbol；
- 标题栏随滚动折叠，展开时展示作者/问题上下文，收起时展示单行标题；
- 沉浸式隐藏标题栏和底栏，返回先退出沉浸式；
- 正文继续使用原生文档渲染，链接、图片、代码、公式的样式服从鸿蒙主题；
- 收藏弹窗、评论层和更多面板使用系统半模态，不用全屏透明 `Column` 模拟；
- 加载失败、登录失效和风控状态在正文区域展示，不改变底栏按钮顺序。

### 8.3 详情更多和导出

上游完整操作包含不在当前鸿蒙范围内的 AI 项。移除这些项且不留空位后，保留项顺序应为：朗读、分享、复制链接、沉浸式、导出、分享 Markdown、在电脑中打开。当前鸿蒙更多面板的“复制链接 / 分享 / 朗读 / 导出”顺序需要在相关能力接线时统一。

导出面板保持上游纵向结构：标题、PDF、HTML、长图、复制 Markdown、评论数量 Slider、含评论长图、开源项目说明开关、进度、右下取消。格式行用 HarmonyOS 设置式操作行，文件位置由系统 Picker 选择。PDF 未实现前可保留首行禁用并说明原因；其他未排期能力不长期放置禁用按钮。

日报正文复用文章阅读排版，但其返回标题、来源、原文跳转和错误状态独立，不应把网页错误弹窗做成文章正文卡片。

## 9. 想法、话题和用户主页

### 9.1 想法详情

上游顶部左侧返回，中间显示作者语境，右侧是分享/更多；正文依次展示作者、文字和媒体、话题、时间/IP、投票或互动统计，评论入口位于下方操作区。鸿蒙现有 `PinDetailPage` 功能覆盖较完整，但屏蔽作者/关键词/话题不应长期作为正文中的三个高强调按钮，应收进最右“更多”面板，正文只保留高频互动。

### 9.2 话题详情

这是鸿蒙当前明确缺失的生产页面。上游布局为：

- 左返回、话题名、右分享；
- 话题头像/名称、简介和统计；
- “关注话题”与“发想法”；
- “讨论 / 想法 / 待回答”三 Tabs；
- 讨论使用“精华 / 最热 / 最新”，想法使用“最热 / 最新”筛选 Chips；
- 下面是统一 Feed。

迁移可行性高，复用 Feed、话题实体、关注和 P4 发想法即可。应新增 `TOPIC` 强类型路由；话题 Chips 点击不再降级为无动作或搜索。

### 9.3 用户主页

上游用户页使用约 240dp 的可折叠头部，包含头像、名称、简介、统计和关注；“搜索 TA 的创作”固定在右上。头部下面是可横向滚动的十个 Tabs：回答、文章、动态、收藏、提问、想法、专栏、粉丝、关注、关注订阅。

鸿蒙当前实现用户头、关注、屏蔽和部分内容分类，建议：

- 保持头像/身份/简介/统计/关注的上游层级，不用多个等权胶囊按钮填满头部；
- 搜 TA 固定右上，拉黑、屏蔽推荐、屏蔽其提问收进更多面板；
- Tabs 横向滚动，不压缩字号；未实现分类暂不显示，后续按上游顺序插入；
- “关注订阅”子页仍按专栏、话题、问题、收藏夹顺序；
- 宽屏时头部在右侧详情上方，Tabs 仍位于头部下方，不迁移到左侧全局导航。

## 10. 评论层

上游评论 UI 同时承担根评论、子回复、图片操作、删除确认和回复编辑。鸿蒙 `CommentLayer` 已具备根/子列表、回复、点赞、删除和底部输入，功能基础充分。

目标结构：

- 顶部左侧为返回上层回复或关闭，中间为“评论/回复”，右侧为关闭或排序；
- 排序 Chips/Tabs 紧随标题栏，根评论和子回复不混用滚动状态；
- 评论行按头像、作者/身份、正文、时间/IP、回复/点赞/更多排列；
- “查看全部回复”位于对应根评论下方，不跳到页面顶部；
- 输入框固定在底部安全区之上，回复对象提示在输入框上方，发送在右；
- 图片长按使用系统操作菜单，删除使用警示色并二次确认；
- 手机可使用接近全高的系统半模态，深链直达评论时可使用完整 `NavDestination`；宽屏放在详情右侧栏或受控宽度面板。

## 11. 收藏、通知与历史

### 11.1 收藏

收藏夹列表保持普通标题栏、列表和右下新增 FAB；当前鸿蒙正文顶部“新建收藏夹”按钮应迁移为 FAB 或标题栏右侧新增。收藏夹行从左到右为名称/公开状态与说明、统计、行级菜单，整行打开。

收藏夹内容页保持返回在左，标题居中/靠起始，导出和更多在右；正文先显示说明与统计，再显示内容列表。批量 HTML 导出仍从右上菜单进入，导出选项与进度使用系统对话框，不能把导出按钮插到每条内容中。

### 11.2 消息中心

上游消息中心为居中标题“消息”，左返回，右侧“全部已读”和“设置”；正文先是通知分类，再是邀请入口，分隔后为会话/通知列表。分类详情使用独立时间线页，私信页底部固定输入框。

鸿蒙 `NotificationPage` 和 `NotificationSettingsPage` 已实现主列表和部分筛选，仍需：

- 把全部已读和设置稳定放在标题栏右侧；
- 增加分类时间线强类型路由；
- 邀请和私信未实现前不伪装成可点击空页面；
- 私信若进入路线，输入固定底部，发送在右，键盘弹出后不遮挡最近消息；
- 系统通知开关应跳转或映射 HarmonyOS 通知授权，不复制 Android 通知渠道设置。

### 11.3 历史

上游在线历史标题栏右侧菜单包含“查看本地历史”和“清除历史”；列表行的删除是行级更多操作。鸿蒙当前把本地和在线内容合并在 `ReadHistoryPage`，这种平台整合可以保留，但需要：

- 标题栏右侧提供来源筛选和清空，正文顶部只保留简短隐私说明；
- 按日期或来源分组，标题/时间/来源为主次文本；
- 整行打开，删除固定在行尾或更多菜单；
- 清空明确说明是否同时影响知乎在线历史，必须二次确认；
- 退出登录后在线记录区域切换为登录提示，本地记录仍可查看。

## 12. 创作、草稿与媒体

### 12.1 写回答

上游标题栏为左返回、中间题目/“写回答”、右发布。正文依次是问题上下文、编辑器、图片/格式工具和草稿状态，目录生成属于编辑辅助。

鸿蒙 `AnswerPublishPage` 已完成编辑、草稿、图片与发布确认，但当前“退出 / 保存草稿 / 发布回答”主要位于正文。UI 收敛时应把退出/返回置左、发布置右；保存草稿可在工具区或更多菜单，自动保存状态放在标题或编辑器下方。真实发布继续保留最终确认，不改变 P4 的安全门禁。

### 12.2 发想法与草稿箱

上游发想法页同样是左返回、标题“发想法”、右发布；正文顺序为标题、内容、图片、已选话题、推荐话题。鸿蒙保留本地草稿和最终确认，并将“保存草稿”降为次操作。草稿箱标题栏右侧刷新，列表按更新时间排序，整行恢复草稿；删除使用行级菜单和确认。

### 12.3 视频、图片、扫码和分享

- 视频全屏，返回/关闭在左上，播放控制贴近底部安全区；横竖屏切换不改变控制顺序；
- 图片预览使用深色全屏背景，关闭在左上，图片计数/更多在右上，保存/分享通过系统菜单；
- 扫码页标题栏返回在左，取景框居中，权限/手电筒/相册识码按系统能力放在底部；
- 电脑端登录确认页必须突出登录目标和风险说明，拒绝在左、确认在右；
- 分享统一调用系统分享面板，不在应用内复制 Android 分享目标网格。

## 13. 账号、设置和 P5 高级页面

### 13.1 设置首页

上游账号页先显示登录/账号头部和收藏、关注订阅等快捷入口，随后为设置第一组：身份管理、外观与阅读体验、朗读与播放、推荐系统与内容过滤、系统与更新、开发者选项；“关于”组依次为应用/版本、GitHub、项目协议、开源许可。

鸿蒙 `P1Shell.settingsPage` 当前以主题卡和一组全宽按钮为主，需要改为：

- 账号头部和快捷入口在最上方；
- 设置使用 `ListItemGroup + ListItem`，左侧 Symbol/主次文本、右侧值/开关/箭头；
- 普通导航项不使用品牌色填充，危险操作单独分组；
- 页面级标题由 `NavDestination` 提供，不在正文重复；
- 设置搜索固定在大标题栏右侧或首组之前；
- 宽屏左栏显示设置分类，右栏显示当前子页。

### 13.2 推荐、过滤与屏蔽

推荐设置按上游顺序保留：推荐算法、登录推荐、启动刷新、质量屏蔽、规则型内容过滤、已关注过滤、关键词/用户/话题开关与阈值、精确规则、屏蔽列表、屏蔽记录、统计。布尔项用尾部 Switch，枚举用尾部当前值和箭头；依赖主开关的子项禁用但不移动。

屏蔽列表从上到下应为统计卡、右对齐导入/导出、关键词/用户/提问者/话题 Tabs、当前列表，新增 FAB 在右下。端侧 NLP 已明确排除，不显示 NLP Tab。现有 `BlockingRulesPage` 已有关键词/用户/话题和 JSON 往返，但导入导出在页面底部、添加为正文按钮，需要重排。

屏蔽历史的整体清空放在标题栏右侧，单项删除在行尾，正文顺序为标题、作者、警示色原因、时间；隐私说明位于列表前，不抢占操作位置。

### 13.3 外观、阅读与系统设置

外观页保持上游分组顺序：主题、阅读、信息流、回答页、底部导航、交互/分享、搜索、平台导航。具体处理：

| 上游能力 | HarmonyOS 处理 |
| --- | --- |
| 跟随系统/浅色/深色 | 单行枚举，复用现有主题状态 |
| Material You 动态取色 | 转为“使用系统主题色”，不复制壁纸取色实现 |
| 字号、行高、段间距 | Slider + 即时预览，使用 fp/vp 并尊重系统字体缩放 |
| Feed 缩略图/卡片样式 | 原地刷新现有 Feed |
| 标题栏/底栏自动隐藏 | 接详情滚动状态 |
| 回答切换手势 | 与系统返回、文本选择、图片缩放仲裁 |
| Android 预测性返回、Material popup、WebView 阅读器 | 平台裁剪，不留入口 |
| Duo3 实验品牌 | 只保留已产品化的独立设置，不迁移实验总开关 |

“系统与更新”只保留适用于 HarmonyOS 的版本信息、日志/诊断和应用市场跳转，不复制 Android APK 下载更新器。身份管理、阅读设置、设置搜索、颜色方案等尚无鸿蒙生产子路由，应随设置壳逐页补齐或明确裁剪。

### 13.4 开源许可

入口继续位于“关于”分组末尾。页面使用大标题和依赖列表，每行显示依赖名称，以及“许可证 · 摘要”次级文本；点击进入应用内许可正文或经过 HTTPS/主机校验的项目地址。依赖清单应从鸿蒙实际打包依赖生成，不能展示 Android/Kotlin/Compose 依赖。

## 14. HarmonyOS 统一组件和视觉规范

全应用先统一组件，再逐页调整，避免每个页面继续自绘一套按钮和卡片。

| 语义 | HarmonyOS 组件建议 | 位置规则 |
| --- | --- | --- |
| 页面壳 | `Navigation` + `NavDestination` | 返回左、标题中/起始、页面操作右 |
| 长列表 | `List` + `ListItemGroup` | 主次文本左，状态/操作右 |
| 分类切换 | `Tabs` | 紧随标题/头部，支持横向滚动 |
| 高频主操作 | 普通/胶囊 `Button` 或 FAB | 每页一个最高强调动作 |
| 图标操作 | `Button` + 官方 `SymbolGlyph` | 标题栏/底栏固定边缘位置 |
| 二值设置 | `ToggleType.Switch` | 行尾，整行可点击 |
| 枚举设置 | 设置行 + 当前值 + 箭头 | 点击整行打开菜单/单选面板 |
| 临时操作 | 系统菜单/半模态 | 返回先关闭，宽屏限制最大宽度 |
| 危险操作 | 警示色 + 二次确认 | 不与普通主操作同色同级 |
| 文件/媒体 | 系统 Picker/分享面板 | 用户选择位置和目标 |

当前资源已具备 30fp 页面标题、20fp 标题、16fp 正文、14fp 次文本、12fp 辅助文本，以及 20vp 页面边距、18vp 卡片内边距、16vp 圆角等基础令牌。后续应把这些令牌用于统一组件；不要以所有内容都套 16vp 大圆角卡片的方式替代真实的信息层级。

所有页面还需满足：

- 只使用真实存在的系统 Symbol；
- 浅色/深色/系统主题无硬编码 Material 色；
- 200% 字号下主文本可换行，尾部开关和操作不覆盖；
- 触控区域和无障碍文本完整；
- 状态栏、底部安全区、折叠铰链和软键盘正确避让；
- 加载、空、错误、登录失效和风控状态使用同一套状态组件。

## 15. 平板、折叠屏与自由窗口

上游当前主要是手机单列 Compose，并没有成熟的 WindowSizeClass、NavigationRail 或列表—详情宽屏实现。因此，上游只提供信息架构和手机位置基线；宽屏必须按 HarmonyOS 规范设计。

| 窗口宽度 | 全局结构 | 页面处理 |
| --- | --- | --- |
| `< 600vp` | 单栏 Stack + 底部顶层导航 | 严格保持上游手机端上下/左右位置 |
| `600–839vp` | 父页/详情 Split | Feed—详情、设置—子页、收藏—内容可双栏 |
| `≥ 840vp` | 左侧顶层导航 + 内容区 | 顶层导航项顺序不变；内容区继续按需双栏 |

具体要求：

- 根 `P1Shell` 不再永久固定 `NavigationMode.Stack`，而是由窗口宽度选择 Stack/Split/受控布局；
- 600vp 起，左栏保留父列表，右栏替换详情，系统返回先关闭/清空详情选择；
- 840vp 起，底部导航迁到左侧，选中项、顺序、徽标和回顶行为不变；
- 设置在宽屏使用左分类右详情，评论和导出面板限制最大宽度；
- 窗口跨断点后不重新请求数据，不丢滚动位置、编辑草稿、选中 Tab 和返回栈；
- 折叠屏展开态按当前可用窗口宽度判断，不按设备型号写分支。

## 18. 验收门禁

### 18.1 页面覆盖

- 本文总表中每个“已实现/部分实现”页面都有 API 26 实机或模拟器截图基线；
- “未实现”页面必须新增路由和验收用例，或在计划中明确不进入产品范围；
- 所有入口可从正常产品导航到达，诊断 Probe 不作为业务页面替代品。

### 18.2 位置和交互

- 360vp 手机逐页核对标题栏、Tabs、正文、底栏/FAB 和临时面板的顺序；
- 返回在左、页面操作在右，详情“更多”最右，创作“发布”最右；
- 列表行主次文本与行尾操作不交换；
- 键盘弹出不遮挡输入框/发送/发布，返回先收键盘或关闭临时面板；
- 600vp/840vp 验证分栏和侧边导航，导航项顺序与手机一致；
- 跨断点、旋转、后台恢复后，返回栈、选中 Tab、滚动位置和草稿不丢失。

### 18.3 HarmonyOS 质量

- 工程和 HAP 的 `targetSdkVersion`、`compatibleSdkVersion` 均为 API 26；
- 浅色、深色、系统主题和 200% 字号全部通过；
- 系统 Symbol、Picker、分享、通知权限、半模态和安全区均使用 API 26 可用能力；
- 自动化不只判断页面存在，还检查关键控件位置顺序、可见性、无障碍文本和状态恢复；
- 长图必须检查实际像素正文，HTML/Markdown/PDF 必须检查内容结构，不能只检查文件存在或大小。

## 20. 最终判断

全应用迁移在 API 26 上总体可行，且大多数页面已有功能底座。正确的实施重心应从“逐页补一个按钮”转为“先统一根导航和页面壳，再按上游位置约束收敛各页面”。最优先的三项是：重构 `P1Shell` 顶层导航、建立通用 HarmonyOS 页面/设置组件、统一详情与评论的标题栏/底栏/半模态。完成这三项后，P0–P5 已有功能才能形成一致的产品 UI，后续话题、设置子页、导出和宽屏也能在同一布局体系中继续扩展。
