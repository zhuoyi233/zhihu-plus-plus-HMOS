# 服务器已读历史同步

行为参考：[上游 PR #762](https://github.com/zly2006/zhihu-plus-plus/pull/762)。这里只移植服务器已读同步，不涉及该 PR 的扫码入口等其他变更。

- 已登录账号进入或返回首页、刷新或加载下一页时启动后台同步，所有推荐模式共用一个任务；同一账号 60 秒内不重复启动。最后尝试时间保存在数据库中，重启、仓库重建及请求失败均不会绕过节流；并发实例通过条件更新竞争一次同步资格。游客不请求历史接口。
- 接口为 `https://api.zhihu.com/unify-consumption/read_history?offset=0&limit=50`，使用现有会话；下一页只接受同一 HTTPS 接口的 offset/limit 游标，单页请求最长 15 秒。
- 首次扫描至末页；之后以最后一次完整成功同步的阅读时间为边界，包含所有同秒记录，遇到严格更旧记录才停止。不因内容 ID 已知、页面全部重复或无法映射而停止。检测到时间倒序异常或缺失时继续扫描至末页。请求失败、游标循环等情况不推进边界，已导入身份保留，下一次从首屏重试。
- 首页推荐请求与同步并行，前台过滤最多等待历史首屏 300ms；同步失败不阻塞推荐。本机打开记录与远端已读均在开启“智能内容过滤”且未启用反向屏蔽时隐藏，保留已关注作者例外；本机已读无需达到曝光次数阈值。
- 后续同步结果只过滤首页未浏览的尾部，不刷新整页、不重新请求推荐、不追加曝光统计。异步查询期间继续滚动时也会保护新浏览到的前缀；离开首页时解除通知订阅，再进入时重新检查。
- schema v9 新增 `remote_read_content`（账号与类型/ID 组成的内容身份联合主键）及 `remote_history_sync`（账号的成功时间边界）；v10 增加可空的 `last_attempt`，保留既有成功边界与远端身份，首次升级不误触节流。远端与本机查询均按候选去重、每批最多 500 个身份；远端表不复制 Cookie、正文或标题。
- 本机阅读身份和远端阅读身份均持续保留，不自动过期；历史页最多展示 1000 条，该展示上限不再触发数据库裁剪。手动清理 7 天前曝光数据只按时间删除，不因统计超过 10000 次而清空其余数据，也不删除实际已读身份。
- 在线浏览记录页“清除历史记录”成功后，同时取消在途同步并清除当前账号的远端已读身份和时间边界。单条删除在线历史不撤销已读标记，与上游保留已读事件的行为一致。

与安卓实现的存储区别：鸿蒙端使用独立表保存远端来源，避免把批量同步结果混入本机实际打开记录，并按当前已验证账号 ID 隔离远端数据及同步进度。本机实际打开记录仍按既有本机历史保存；首页综合本机已读、远端已读及曝光记录过滤。

设备测试的每个用例均使用独立的 `remote_history_test_*.db`，结束后关闭并删除，不读写生产数据库。网络响应被测试夹具替代，RDB、生产 SQL、解码、同步、持久化与过滤实际执行。设备报告、构建日志与 SQL 基准保存在 `.tmp/history-parity/`。

基准比较的是强制扫描对照与当前生产查询，不代表历史版本的前后性能，也不代表首页端到端性能。真实账号联网同步与这些固定输入测试分别记录；本测试套件不声称完成了“网页阅读指定回答后，在真实推荐流中逐条对照”的人工验收。

## PR #93 合并后的数据库迁移
