# P2 首页 Feed UI 验证记录

> 基线：DevEco Studio 6.1.1 Release、HarmonyOS 6.1.1（API 24）
> 范围：首页 Feed UI 与纯状态控制器；不包含端侧 AI、WebView 和生产网络实现

## 行为边界

- UI 只依赖 `FeedRepository`，不会把 rawfile fixture 或静态数据伪装成生产网络结果。
- 首次加载、刷新、分页、空态和失败态由 `HomeFeedController` 统一管理。
- 刷新开启新代次；更早的刷新、分页响应及页面离开后的响应不能覆盖当前列表。
- 分页请求互斥，并按 `target.kind:target.id` 保留第一次出现的条目，避免同一内容因不同 Feed 外壳重复展示。
- 分页失败会保留现有列表和滚动上下文；错误条目的“重试”只重试加载更多。失败后自动触底被锁住，避免反复请求风暴。
- 失败文案不包含底层异常和响应体。已有列表时显示可恢复错误；首次失败显示整页重试。
- 问题、回答和文章卡片分别映射到已有强类型 `P1Destination`，不使用 URL 字符串驱动内部导航。

## UI 与无障碍约束

- 根布局固定为满屏 `Stack(TopStart)`，列表不会因条件分支退化为空白或居中到错误位置。
- 字体沿用现有 `fp` 资源；标题和摘要不设置固定行数或省略号，允许系统大字体自然换行。
- 页面沿用现有主题色资源和 Navigation 安全区，不写死深浅色。
- 搜索、刷新、重试、加载更多和每张卡片均提供稳定 `id`；卡片与主要按钮提供可读的无障碍文本。
- 当前刷新入口是明确按钮；生产数据接入与 API 24 设备验收时再决定是否补充系统 `Refresh` 下拉手势，不能用未验证 API 替换已可测入口。

## 纯状态测试

`entry/src/test/HomeFeedState.test.ets` 覆盖 8 个用例：

1. 首屏加载与页内去重。
2. 分页互斥和服务端游标传递。
3. 首次错误可重试并进入空态。
4. 最新刷新优先以及离页结果隔离。
5. 三类卡片到强类型目的地的映射。
6. 跨页合并保留首次出现顺序。
7. 服务端协议枚举不会直接显示给用户，缺少可读动作文本时统一降级为“推荐内容”。
8. 分页错误只重试原游标，刷新与离页会取消旧请求并隔离旧 generation。

该测试文件已由主代理统一注册到 `List.test.ets`。

## API 24 集成与设备验收

- `DefaultFeedRepository` 已作为 `HomeFeedPage` 的生产默认数据源，`P1Shell` 首页已替换为真实游客 Feed；未使用 fixture 或静态假数据。
- `ZhihuPlus_API24` 冷启动后成功显示真实 Feed 列表，刷新后仍保持列表态；连续向下 fling 后继续出现新卡片，未出现分页错误提示。
- 首页“显示”入口可进入 P1 主题页，主题页的“技术实验室”入口可回到全部 P0/P1 原型，原有能力未被首页替换切断。
- 设备截图发现原始动作枚举泄露后已修复为可读降级文案，并由第 7 个纯测试锁定；大写、小写和普通英文协议 verb 均不会原样泄露。
- 本批未实现问题/回答/文章正文页；卡片目的地映射由纯测试覆盖，真实内容导航留给后续正文纵向切片验收。
- 系统/浅/深主题及大字体在 P1 已验收；P2 卡片的极端字体与折叠屏布局仍需在后续 UI 综合验收中复测。
