# 上一答预览与切换动画计划

日期：2026-10-29  
代码基线：`c420104f`  
状态：P1/P2 已实施并通过编译与 Hypium（1078/1078）；API 26 平板模拟器完成双向切答与位置回归。
拖动过程连续帧、冷缓存/慢网等待提示与性能对比尚未覆盖，详见 §9。

## 1. 目标与范围

针对“返回上一答的预测预览不如下一答”的体验反馈，以当前下一答的整页预览为基准，让上一答也能提前准备真实正文，在拖动时跟手露出，松手后从当前位移连续落位，取消时连续回到原答。

适用于单篇回答页：纵向模式下顶部下拉返回上一答，以及横向模式下右滑返回上一答。电纸书越界翻页等已有切答入口继续共用提交事务。不新增上一答路由，不改变系统返回键含义；连续阅读页不纳入本计划。

“上一答”仍由 `QuestionAnswerNavigator` 的当前排序决定，包括列表外入口回答的“虚拟上一答”；不是另建一份访问历史栈。本计划中的“预测”指手势提交前的内容预览与准备，不引入系统预测返回 API。

## 2. 当前实现与差异

以下为源码事实；它们能够解释体验不对称的风险，但尚不能替代设备复现结论。

| 环节 | 当前实现 | 对上一答的影响 |
| --- | --- | --- |
| 整页渲染 | `ContentDetailPages.ets` 的 `answerPanes` 在根构建树中挂载正式正文与一个候选正文，二者复用 `loadedContent()` / `NativeContentDocument` | 已有双向整页框架，无需另造摘要卡片或截图页 |
| 空闲预取 | `applyState()`、列表回调、页面恢复、拖动取消等入口优先调用 `prefetchNeighborAnswer(false)` | 下一答通常更早获得数据和布局准备时间 |
| 切换收尾 | `applyAnswerMove()` 的 finally 会依次预取下一答和上一答 | 不能简单认定“上一答完全没有预取” |
| 候选挂载 | `prefetchNeighborAnswer()` 同时检查候选是否已存在，并用 `(previous && this.navigatorHasNext())` 阻止有下一答时挂载上一答 | 上一答即使命中全文缓存，也通常没有已准备的正文视口 |
| 方向变化 | `ensureAnswerDragCandidate()` 发现方向不符时卸载原候选，再请求、接纳和挂载目标 | 反向拖动需要重新解析、测量或恢复位置 |
| 返回刚读过的回答 | 提交时 `setAnswerPanes([prepared])` 移除旧正文；`forget(id)` 移除新当前答的预取副本；预取器没有接纳离开正文的公开入口 | 回看旧答不能直接假定保留了原组件或全文缓存 |
| 位置恢复 | `NativeContentDocument.adjustReaderPosition()` 对有保存位置的正文进行恢复与稳定等待，正常收敛条件包含至少 2000ms、距布局变化至少 1500ms；另有 8000ms 超时 | 返回已读长答可能比从顶部进入未读下一答更晚达到 ready；不是所有切换都会固定等待这些时间 |
| 未就绪提示 | 候选未 ready 时显示整页等待区；正式切换等待超过 180ms 后显示“正在准备回答…” | 需要检查顶部只露出窄条时，居中等待内容是否落在屏外 |
| 提交 | 候选解析、视口与标题几何准备完成后，执行 220ms `FastOutSlowIn` 动画，保留候选实例键提交 | 可直接复用连续落位机制，不能在松手时重新创建目标正文 |

关键入口位于：

- [ContentDetailPages.ets](../entry/src/main/ets/pages/ContentDetailPages.ets)：`prefetchNeighborAnswer`、`ensureAnswerDragCandidate`、`applyAnswerMove`、`answerPaneTranslate`。
- [QuestionAnswerNavigator.ets](../entry/src/main/ets/pages/QuestionAnswerNavigator.ets)：`peekId`、`prepareMove`、`commitMove`、虚拟上一答。
- [AnswerSwitchPrefetch.ets](../entry/src/main/ets/pages/AnswerSwitchPrefetch.ets)：独立仓库、单并发、同 ID 请求合并、容量为 3 的全文缓存。
- [AnswerPanePreparation.ets](../entry/src/main/ets/pages/AnswerPanePreparation.ets)：按正文实例键汇合解析与视口就绪状态。
- [ContentDetailState.ets](../entry/src/main/ets/pages/ContentDetailState.ets)：当前只支持一个 `preparedAnswerId`，每次 `admitAnswer()` 都递增加载代次。
- [NativeContentDocument.ets](../entry/src/main/ets/pages/NativeContentDocument.ets)：候选可恢复阅读位置，只有活动正文可写位置、获取焦点。

部分源码注释仍提到旧“预览卡”及当前工作树不存在的 `issue-21-answer-switch-flicker-fix-plan.md`，本方案以可执行代码为依据，不据此推断旧文档内容。

## 3. 交互方案

### 3.1 上一答预览页

复用下一答的正式正文构建器、排版、信息头、主题和安全区处理。上一答预览使用真实内容；预览和落地使用同一正文实例、同一滚动位置。已滚离视口的信息头不强行复制到正文尾部。

| 操作 | 当前回答 | 上一答预览 | 松手结果 |
| --- | --- | --- | --- |
| 纵向：顶部继续下拉 | 沿 Y 轴向下移动 | 从屏幕上方进入；先露出目标视口的下缘 | 达阈值继续向下落位，否则一起回位 |
| 横向：向右拖动 | 沿 X 轴向右移动 | 从屏幕左侧进入 | 达阈值继续向右落位，否则一起回位 |
| 拖动中折返 | 位置连续跟随手指 | 回到零点后按新方向选择候选 | 不沿用上一方向的目标或提交资格 |
| 没有上一答 | 保持当前页 | 不显示空白候选或等待提示 | 不触发切答 |

已有全局问题标题沿用下一答的规则：纵向切答淡出，横向同轴移动；落地后依据目标自己的标题几何和滚动位置接管。底部操作栏保持单实例，拖动和提交期间禁用，不能让预览页提前响应点赞、收藏、分享或评论。首期不添加缩放、旋转、独立淡入或新震动，避免不同部件的运动节奏分离。

### 3.2 返回位置

优先恢复用户离开上一答时的位置：

1. 同一阅读会话、布局条件未变且旧正文仍保留时，直接使用其视口。
2. 组件已淘汰时，使用该回答已有的块锚点、块内比例及 `atEnd` 语义恢复。
3. 从未读过或没有有效保存位置时，从顶部进入；锚点失效时按现有恢复策略降级，并记录可验收的结果。

例如 A 在底部切到 B，再从 B 顶部下拉，应预览并回到 A 的原底部附近；横向离开 A 的中段再右滑返回，也应保持原阅读段落。不能先预览 A 顶部，再在提交后突然跳到底部。

视口恢复失败应回弹留在当前答并提示重试。若后续决定允许“从头打开”的降级，必须先让预览同步到从头打开的状态，不在落地后悄悄改位置。

### 3.3 未就绪与失败

正文未准备好时，在已经露出的预览区域靠近两页接缝处显示“正在准备上一答…”；下一答对应显示“正在准备下一答…”。等待区随候选一起移动，使用页面背景和 `resolvedThemeColor`，不伪造作者、摘要或统计。

松手达到阈值后，保留已产生的拖动位移，等待目标具备提交条件；期间保留当前身份和正文。目标准备好后再完成剩余路程。网络失败、目标失效或准备超时则回位，当前索引、互动身份和阅读记录保持原值。沿用现有 180ms 延迟等待提示与超时机制作为首轮基线，不叠加永久等待。

## 4. 动画约定

两方向共用一套参数和状态机，上一答只改变符号。

设切换轴的实际视口跨度为 `E`、当前带阻尼位移为 `d`：

| 页面 | 拖动时的位置 | 切到上一答的结束位置 |
| --- | --- | --- |
| 当前答 | `d` | `+E` |
| 上一答 | `d - E` | `0` |
| 下一答 | `d + E` | 不参与本次提交 |

纵向 `E` 取有效页面容器高度，横向取宽度，沿用当前坐标体系。取消时 `d → 0`；上一答提交时 `d → +E`；下一答提交时 `d → -E`。拖动期间直接更新阻尼位移，不对每次手势事件追加定时动画。

首轮保持现有参数：纵向最大拖动 200vp、横向 300vp，阻尼系数 1.2，阈值分别 80vp / 46vp，并沿用用户灵敏度换算；提交与当前取消路径使用 220ms `FastOutSlowIn`。现有注释有“弹簧回位”表述，但主要取消路径实际调用该定时曲线，实施时一并对齐注释。

状态流程：空闲 → 跟手预览 → 松手后等待就绪（必要时）→ 完成平移 → 同步提交 → 空闲。未达阈值、取消或失败走“回位 → 空闲”。离页、账号变更、系统中断应作废事务；旧请求、旧布局回调和动画计时器不得再推进索引。

暂不因返回较慢就缩短动画或降低阈值。先区分网络获取、解析、位置恢复、布局和动画耗时，再按对比录像调参。当前动画用时长加 20ms 的定时器结算；不能把定时器到期当成真实渲染帧完成的证明。

## 5. 实现设计

### 5.1 对称准备，保留最多三个正文实例

推荐将当前“正式页 + 单候选”扩展为有界的“上一答 + 当前答 + 下一答”，仅保留当前排序中已知的相邻回答。当前答优先完成，随后串行准备邻答；手势明确指向的目标优先于尚未发出的后台任务。只读 `peekId(-1/1)`，后台准备不隐式翻页。

切到下一答时，将离开的当前正文保留为上一答，尽量保留其实例键、解析结果和视口；切到上一答时对称处理。非相邻正文及时淘汰，不随连续切换累积组件。全文缓存仍有独立容量上限，组件数与数据缓存数分别统计。

这不是简单删除 `(previous && this.navigatorHasNext())`：当前 `candidatePane()`、`candidateDirection` 和控制器都假定只有一个候选，直接挂两份会互相覆盖提交代次。需要先完成下面的模型调整。

### 5.2 分离“可预览实例”和“本次提交目标”

- 为上一答、当前答、下一答显式保存角色与稳定文档键；按目标 ID / 方向取得候选，不再使用“第一个非当前正文”。
- 将预览登记与切答事务分离：邻答可以同时处于只读准备态，但每次手势只绑定一个目标、一个事务 token。控制器不得因另一邻答准备完成而使当前拖动目标失效。
- 稳定文档身份与请求代次分别管理，避免复用旧实例时误用已过期的 `loadGeneration`；提交接纳已有视图模型，不能为获得新资格而换键重建正文。
- 导航器与详情控制器仍在目标、会话和相邻关系校验通过后同步交接；任一校验失败都不得留下索引前进但正文未切换的半提交状态。
- `AnswerPanePreparation` 继续按实例键保存解析和视口状态；只等待本次选中的目标。淘汰、布局失效和会话重置必须撤销对应 ready。

### 5.3 位置与布局

保留的旧正文视口是上一答快速预览的首选。淘汰后恢复时，先取得最新会话锚点，避免只依赖可能尚未完成的持久化写入。候选可以读取和恢复位置，但取消预览不能写入新阅读进度或历史。

窗口宽度、字号、行高、信息头布局或内容版本变化时，旧视口不能直接视为 ready：保存锚点后重新测量和恢复。`NativeContentDocument` 中的候选角色必须能随活动文档切换正确更新，不能依赖普通参数在复用实例后自动刷新；沿用活动文档 AppStorage 信号并补齐失活/再激活测试。

首期通过保留旧视口和提前准备消化恢复等待，不直接删除现有稳定窗口。若仍明显迟缓，再单独验证“布局未变且视口已保留”的快速路径；图片、公式和链接卡片异步增高时仍须锚点校准。

### 5.4 数据、失效与资源预算

- 沿用独立预取仓库、网络并发 1、同 ID 合并。前台插队只影响排队任务，不能宣称能抢占已经发出的请求。
- 离开的已加载正文可进入会话邻答缓存；缓存接纳必须校验问题、账号/会话代次和回答 ID。互动后的旧数据不能回流覆盖最新赞同、收藏等状态。
- 账号、问题、排序、屏蔽规则变化和页面销毁时，清理受影响的邻答、视口资格和提交 token；隐藏页面暂停准备，迟到结果不能重新挂载。
- 预览不请求热评、不播放媒体、不抢焦点、不触发点击、选词、音量翻页或正文越界切答；隐藏候选不进入无障碍导航树。重点核查所有回调，不能只依赖点击穿透设置。
- API 23 上记录两槽基线与三槽方案的内存、首屏耗时及滑动帧表现。若三槽成本不可接受，降级为“当前 + 方向候选”，保留前后全文与锚点；纵向贴顶优先准备上一答、贴底优先准备下一答。该降级不承诺横向任意方向首帧都已就绪，需单独报告体验差异。

## 6. 实施顺序与交付

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0：复现与基线 | 在相同内容上录制下一答与上一答，区分缓存命中/未命中、首次进入/返回已读；记录准备各阶段时间 | 能指出慢在数据、挂载、恢复还是动画，不凭最终截图判定 |

| P2：预览与动画接线 | 上一答提前测量和恢复，接缝等待提示，统一方向和落位，核查标题/底栏/焦点接管 | 预览与落地正文、位置一致；取消连续；下一答无退化 |
| P3：验证与调优 | 按下节执行自动化和设备矩阵，比较资源开销；必要时单独调恢复快路或动画参数 | 有前后录像、阶段耗时和实际验证记录，未覆盖项明确保留 |

### 7.2 设备与视觉验收

默认 `ZhihuPlus_API23` / `127.0.0.1:5555`；API 26 和真机作为后续补充。使用相同回答、相同窗口、相同手势距离比较前后方向，至少覆盖短文、长文、含图片与公式的回答。

| 场景 | 验收重点 |
| --- | --- |
| 纵向顶部下拉、横向右滑 | 拖动早期、中段、临界点均能看到正确方向的内容；已 ready 的目标不闪等待区 |

| 冷缓存、慢网、断网、目标失效 | 可见等待提示、有限等待、失败回位，当前内容可继续阅读 |
| 首答、末答、虚拟上一答 | 不显示不存在的预览，入口回答可以正确返回 |
| 深浅色、大字号、横屏、窗口变化 | 主题一致、裁切正确；旧尺寸不参与新布局提交 |
| 图片预览、选词、菜单、悬浮按钮拖动、音量翻页 | 手势不串扰，候选无副作用；关闭弹层后原功能正常 |
| 连续往返至少 20 次 | 无实例累积、明显内存持续增长、旧答错位或已读记录重复提交 |
