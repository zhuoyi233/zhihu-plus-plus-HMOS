# P0 技术验证收口摘要

> 收口日期：2026-08-11

## 结论

`p0-validation-plan.md` 中 14 个门禁全部通过，当前没有阻止进入 P1 的问题。签名、真实 Cookie 登录、原生长正文和原生公式四个高风险点均已在 HarmonyOS 6.1.1（API 24）DevEco 虚拟机形成可运行原型。P0 没有引入端侧 AI 依赖、模型文件或推理代码。

## 最终门禁

| 范围 | 门禁 | 结果 |
| --- | --- | --- |
| 工程与设备 | ENV、ID、DEV | 通过 |
| 网络与账号 | NET、SES、ZSE、LOGIN | 通过 |
| 内容渲染 | READ、MATH、IMG | 通过 |
| 系统能力 | DB、LINK、SCAN、BG | 通过 |

真实登录验证覆盖：账号接口 HTTP 200、非空账号响应、加密保存、应用进程重启恢复、退出清理和清理后再次重启游客态。复测结束前已删除真实会话，任何文档和日志均未保存 Cookie 值。

## 已冻结的架构决定

- 只适配 API 24，`targetSdkVersion` 与 `compatibleSdkVersion` 均为 API 24，不增加 API 20 分支。
- 正文使用 ArkUI 原生 AST 与懒加载列表，不以整页 ArkWeb 作为主渲染器。
- 公式 SVG 由 NetworkKit 下载并严格校验，再经 ImageSource 解码为页面持有的 PixelMap；失败只降级当前公式节点。
- Cookie 仅在账号接口校验成功后进入 AES-256-GCM 加密信封，数据密钥保存在 Asset Store。
- URL 安全策略使用共享纯 ArkTS 解析器，精确拒绝伪造域名、userinfo、显式端口与非法转义。
- HTTP 层统一区分认证、超时、限流、客户端、服务端、网络和取消错误。
- Git 不保存签名材料；每台开发机使用 `devecocli` 生成本地调试签名。
- Android 的端侧 AI、模型和推理链路不迁移。

## 进入 P1 后的非阻塞事项

- 将 P0 原型拆入正式的 `core`、`data`、`reader` 等模块边界，并建立 AppStartup 初始化图。
- 将二维码创建、轮询、风控与统一 Session Repository 接通；手动 Cookie 已满足当前 MVP 登录门禁。
- 在真实 HarmonyOS 手机补测相机对焦、暗光、前后台切换和系统权限交互。
- 建立冷启动、长文峰值内存、图片密集文章、弱网和持续滚动的可重复性能基线。
- 发布签名、AppGallery Connect 和升级连续性留在 P6。
