# P0 基础网络验证记录

> 最终验证：2026-08-10；唯一兼容基线：HarmonyOS API 24

## 实现边界

- 使用 NetworkKit `HttpRequest` 发起 HTTPS 请求，连接超时 10 秒、读取超时 15 秒，并在 `finally` 中销毁请求对象。
- HTTP 状态统一分类：401/403 为认证失败，408/504 为超时，429 为限流，其他 4xx 为客户端拒绝，5xx 为服务端临时失败。
- NetworkKit `BusinessError 2300028` 映射为超时，其余传输异常映射为网络连接失败。
- 探针只允许一个活动请求；重复点击会被本地拒绝，取消状态绑定具体请求对象，旧请求结束时不会覆盖新请求状态。
- 探针结果只保留状态码和响应正文，不传播或记录响应 Cookie。

## API 24 虚拟机验证

设备：`ZhihuPlus_API24`，HarmonyOS `6.1.1(24)`。

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| DNS、TLS 与 HTTPS 请求 | 通过 | 知乎公开问题接口返回 HTTP 403，证明请求到达服务端 |
| 认证错误映射 | 通过 | UI 显示 `HTTP 403（需要有效登录态）` |
| 主动取消 | 通过 | 设备端连续触发“运行 HTTP 探针”和“取消”，请求回调结束后状态仍为 `HTTP 探针已取消` |
| 进程稳定性 | 通过 | 取消和 403 分支后应用保持前台，无崩溃记录 |

公开接口在无 Cookie/ZSE 登录态下返回 403 是预期的认证结果，不再与基础网络门禁混为一项；真实 Cookie 的 HTTP 200 成功分支归 `P0-LOGIN-01`。

- `devecocli build --product default --modules entry --build-mode debug`：`BUILD SUCCESSFUL`。
- Hypium 覆盖 200、401、403、408、422、429、503、504、NetworkKit 超时码、普通连接错误和取消文案；本轮报告中网络用例无失败。
- 最终全量 Hypium 共 46 个用例、失败 0。Hvigor 历史运行中即使有断言失败仍曾返回退出码 0，因此 CI 必须同时检查测试报告内容而非只看进程退出码。

## 结论

HTTPS、取消、超时与错误映射均已有代码、自动化或 API 24 设备证据，`P0-NET-01` 通过。登录态验证和加密会话恢复继续由 `P0-LOGIN-01`、`P0-SES-01` 分别负责。
