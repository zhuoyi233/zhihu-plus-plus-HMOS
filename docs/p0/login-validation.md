# P0 登录原型验证记录

> 验证日期：2026-07-20

## 已实现路径

- 游客模式不发起账号请求，也不会隐式删除已经加密保存的登录会话。
- 手动 Cookie 导入使用密码输入框，UI 和测试树只暴露掩码，不显示 Cookie 明文。
- 输入在提交后立即从页面状态清空。
- 登录 Cookie 必须同时包含 `z_c0` 和 `d_c0`；缺失时在本地拒绝，不发起网络请求。
- 合法格式的 Cookie 会携带桌面 User-Agent、`Referer`、`x-requested-with`、`x-zse-93` 和动态生成的 `x-zse-96` 请求 `https://www.zhihu.com/api/v4/me`。
- 只有 HTTP 200 且账号响应包含非空 `id`、`name` 时，Cookie 才会进入加密会话存储。
- HTTP 401/403 视为凭证失效；恢复旧会话时会清理本地密文和 Asset Store 密钥。
- 网络错误、服务端错误和无法识别的响应不会删除已保存会话，避免弱网导致误登出。
- 退出登录会同时清除 Cookie 密文和 Asset Store 数据密钥。

## 自动化测试

新增 6 个 ArkTS 用例，覆盖：

1. `z_c0` 与 `d_c0` 的组合要求。
2. `/api/v4/me` 账号响应解析。
3. 缺字段和非法 JSON 拒绝。
4. HTTP 200 登录成功分类。
5. HTTP 401/403 凭证失效与 503 临时失败分类。
6. HTTP 200 非账号响应拒绝。

Cookie 解析还覆盖重复名称以后值覆盖前值。当前 ArkTS 测试总计 21 个，失败 0。

## 当前结论

游客闭环和手动 Cookie 登录实现已经可运行，安全保存只发生在知乎账号接口验证成功之后。由于测试环境没有合法知乎账号 Cookie，本轮没有验证真实账号的 HTTP 200 成功分支，因此 P0-LOGIN-01 保持“进行中”，不能仅凭单元测试标记通过。

二维码登录不属于本批次。后续先评估知乎二维码接口的稳定性、风控和 Scan Kit 的必要性，再决定是否进入 P0-SCAN-01；不会用二维码路径阻塞手动 Cookie MVP。
