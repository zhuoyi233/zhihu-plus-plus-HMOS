# Zhihu++ HarmonyOS UI 设计规范指导

## 1. 适用范围与使用方式

本文规定 Zhihu++ HarmonyOS 的视觉语言、页面结构、控件行为和体验标准，供界面设计、设计评审与开发还原使用。

规范直接描述应呈现的界面与交互，不依赖某一页面的实现版本。不同业务可以选择不同的信息结构，但颜色、字阶、留白、导航、操作反馈和材质策略必须一致。

阅读顺序：先按 §2 确定页面结构，再按 §3–§8 组合控件与布局，按 §9–§10 补齐状态与交互，最后用 §11 评审设计。“必须”表示约束，“建议”表示需要结合场景判断的设计选择。尺寸、颜色与材质能力边界用于保证设计可落地；代码仅辅助说明视觉规则，构建流程和实现排查不属于本文范围。

## 2. 总体风格与页面构成

### 2.1 视觉方向

**内容优先、中性色打底、主题色强调操作、局部悬浮材质表达层次。** 用户进入页面后，应先看到标题与内容，再看到辅助信息，最后辨认可执行的操作。

- 页面以浅／深色中性背景承载阅读内容；用字体、间距、浅底分组和细分割线区分层级。
- 标题比摘要和统计突出；摘要保持可读，作者、时间、计数使用次级颜色。
- 主题色集中用于主操作、选中态和需要强调的链接；不将整页、整块正文或所有图标染成主题色。
- 圆角卡片表达内容分组，圆形按钮表达独立操作，胶囊表达一组紧密相关的操作或导航。
- 沉浸光感主要落在悬浮导航和操作控件上；正文卡片不普遍玻璃化，不通过叠加多层阴影制造层次。
- 宽屏通过增加内容列数或组织目录／详情利用空间；文字大小继续遵循字号与用户偏好，不按屏幕像素等比放大。

### 2.2 页面类型与视觉结构

| 页面类型 | 视觉结构 | 设计要求 |
| --- | --- | --- |
| 首页 | 顶部搜索胶囊与独立通知圆按钮；自适应列数的信息流；标题、作者、摘要、统计依次排列；底部导航居中悬浮 | 内容层级清楚，列表有稳定节奏；搜索是一级入口；宽屏底栏保持紧凑 |
| 问题详情 | 浅灰问题信息区，标题与统计聚合；补充说明、话题、写回答、回答数量／排序、回答卡片依次展开 | 问题与回答有明确层级；主操作突出；内容分组采用中性表面；底部操作独立于阅读内容 |
| 设置 | 返回圆按钮与左对齐标题；窄窗逐级导航、宽窗目录／详情双栏；分组标题、导航行、分割线；下拉选择与滑杆 | 顶栏位置稳定；每页仅一套返回与标题；配置项语义清楚；顶部按钮轻量悬浮 |

首页的分割线条目与问题页的圆角回答卡片都属于本项目风格。统一的是颜色、字阶、留白和操作语言，不是强制每块内容都加卡片。

### 2.3 页面层次示意

以下为结构示意，不是屏幕尺寸图；具体宽度与安全区由布局计算。

```text
系统状态区
┌ 顶部导航层：返回／搜索 + 标题 + 当前页动作 ┐
│ 内容视口延伸到顶栏后方                    │
│   首屏内容起始让位                        │
│   标题／摘要／统计 → 主操作 → 内容列表     │
│   内容尾部让位                            │
└ 悬浮操作层：导航胶囊，或左右操作胶囊      ┘
系统手势区
```

内容可以从浮层后方滚过，但首项、末项、输入框和可点击操作必须能完整进入不被遮挡的区域。

## 3. 颜色、字体与尺寸

### 3.1 语义颜色

颜色按语义定义并提供浅色、深色两套值。同一语义在各页面保持一致；调整色板时同时更新两种模式及本表。资源名称用于设计与开发对齐。

| 角色／资源 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `page_background` | `#FFFFFF` | `#000000` | 页面底色 |
| `primary_text` | `#111111` | `#F5F5F5` | 标题、正文、主要图标 |
| `secondary_text` | `#666666` | `#A8A8A8` | 摘要、说明、作者与统计 |
| `surface_background` | `#F5F6F8` | `#191A1D` | 问题信息区、设置分组等中性表面 |
| `card_background` | `#FFFFFF` | `#191A1D` | 信息流卡片表面，按组件场景使用 |
| `control_background` | `#E9EBEF` | `#2A2C31` | 非选中控件与中性操作底色 |
| `divider_color` | `#E5E6EB` | `#303238` | 细分割线 |
| `error_text` | `#C62828` | `#FFB4AB` | 错误信息 |

强调色使用适配深浅模式后的主题色，不把默认蓝色当成固定操作色。用户选择的原始颜色需要经过主题解析后再用于界面。

- 主按钮使用主题色背景，文字按背景亮度选择清晰的浅色或深色。
- 开关、复选框、段控、下拉选择和滑杆的选中态跟随主题色；弱强调容器使用同色系浅底，不能任意加固定蓝底。
- 取消、撤销及次要破坏性操作使用中性底色；错误或危险语义不能仅依赖颜色表达。
- 主题变化应即时反映到已打开页面；深色模式下主操作文字、描边、统计和材质下文字均须清楚可辨。

配色示例（`resolvedThemeColor` 为深浅模式解析后的主题色，`onThemeColor` 按背景亮度选择文字颜色）：

```typescript
Button('取消')
  .backgroundColor($r('app.color.control_background'))
  .fontColor($r('app.color.primary_text'))

Button('保存')
  .backgroundColor(this.resolvedThemeColor)
  .fontColor(onThemeColor(this.resolvedThemeColor))
```

### 3.2 字阶与留白

尺寸使用 vp，文字使用 fp；截图中的 px 不可直接作为实现尺寸。以下数值应集中定义为共享资源。

| 资源 | 标准值 | 使用规则 |
| --- | --- | --- |
| `heading_font_size` | 20fp | 页面标题、信息流标题；顶栏字重为 Medium，内容标题可加粗 |
| `body_font_size` | 16fp | 常规正文、设置主文案 |
| `secondary_font_size` | 14fp | 辅助说明、统计等 |
| `caption_font_size` | 12fp | 低优先级元信息，不用于主要阅读内容 |
| `reader_title_font_size` / `reader_title_line_height` | 24fp / 34fp | 阅读标题，不将所有顶栏放大到该字号 |
| `display_font_size` | 30fp | 特殊展示层级，常规列表与设置页不默认使用 |
| `page_padding` | 12vp | 页面基础外边距 |
| `card_padding` / `card_radius` | 18vp / 16vp | 标准卡片内边距与圆角 |
| `spacing_xsmall` / `small` / `medium` / `large` | 4 / 10 / 14 / 24vp | 从紧密关联元素到分组间距，优先复用 |

首页分割线条目的左右留白为页面 12vp 加条目内部 8vp，合计 20vp；卡片模式用卡内 18vp。不要将两套内缩重复叠加。阅读正文需尊重用户的字号、行高、段间距和横向留白配置，不能用这张表覆盖用户设置。

## 4. 顶栏与导航

### 4.1 结构与操作

普通二级页采用“左侧返回圆按钮 + 左对齐单行标题 + 右侧当前页动作”的结构。返回按钮、标题、右侧动作视觉上属于同一条顶栏；目录切换到子项时更新标题，不在正文里再添加一条相同标题栏。

标题为 20fp、Medium，右侧圆按钮为 40 × 40vp、图标尺寸为 20vp，内容行高 48vp。标题起点必须避开返回按钮及其点击区域，并与按钮保持明确间距；不能让标题压住按钮，也不能重复预留空间造成过大空白。

- 右侧仅展示当前页有效动作；切换页面后，菜单内容同步变化，不保留上一页的操作。
- 顶栏图标使用 `primary_text`，按钮底色使用中性材质，不使用默认系统蓝强调普通导航。
- 返回手势与返回按钮执行一致的导航语义。设置窄窗先回内部上一级，目录再离开设置；宽窗中，嵌套子项先返回父项，顶层分类则退出设置。
- 设置页仅绘制一条顶栏。双栏中的详情不重复绘制同名标题和返回按钮。
- 长标题单行省略时，正文仍要有完整内容或可访问名称；不能压缩右侧按钮至不可点击。

### 4.2 页面允许的变化

| 页面类型 | 顶栏规则 |
| --- | --- |
| 首页 | 保留搜索胶囊和通知按钮；一级页不增加返回箭头 |
| 设置及普通管理页 | 返回圆按钮、左对齐标题、右侧有效动作；标题与动作随内容切换 |
| 问题页 | 首屏显示“问题”，问题标题离开正文可视区后切换为具体标题；保留日志／分享动作 |
| 回答／文章 | 展示内容身份；折叠时机由正文几何位置决定，不机械套用问题页阈值 |
| 私信会话 | 使用不透明顶栏，防止消息与标题透叠 |

问题页标题切换时，后方内容进入模糊区域。不能把完整问题标题同时常驻顶栏与首屏正文而造成冗余；回到顶部后恢复“问题”标签。

### 4.3 覆盖式滚动与安全区

首屏让位由状态栏与标题栏共同决定。标题栏内容区域高度为 56vp，其中控件内容行高为 48vp；整体起始让位最小为 94vp。信息流首项可上浮 10vp，让内容贴近搜索胶囊下沿：

```text
普通内容起点 = max(94vp, 状态栏高度 + 56vp)
信息流内容起点 = max(56vp, 普通内容起点 - 10vp)
```

- 滚动视口延伸到顶栏后方，只有首屏内容起点让位；内容上移时可自然经过材质下方。
- 不将整个滚动区域永久压到顶栏下方，否则顶栏与内容之间会出现割裂。
- 不把顶栏额外模糊区域再次计入内容起始留白。
- 标题栏背景按页面类型集中管理：普通页面从首屏轻量背景过渡到滚动态模糊；需要常驻背景的详情首帧即提供可读背景；聊天使用不透明底色。
- 下拉刷新指示器在顶栏下方可见；底部加载指示器在悬浮底栏上方可见。

## 5. 内容列表与问题详情

### 5.1 信息流

信息流条目顺序为：**标题 → 作者 → 摘要 → 类型／赞同／评论等元信息与更多操作**。不增加重复说明条目来源的“推荐内容”头行。

- 标题是最强视觉锚点；摘要以有限行数预览，全文在详情阅读。
- 作者头像辅助识别，不挤占标题与摘要；无头像时保留相同尺寸的中性占位，避免布局跳动。
- 统计与更多按钮处于低优先级层；点击更多不应误触整条内容导航。
- 分割线模式用同底色、细线和留白；卡片模式用完整圆角表面与内边距，不同时加重描边和阴影。
- 信息流样式与列数分别决定；不能将“宽屏”强制绑定为卡片样式。
- 加载更多和刷新保留现有内容，避免整页闪空导致阅读位置丢失。

### 5.2 问题详情

按以下顺序组织内容：

1. 问题标题与浏览／关注／评论统计聚合在中性浅底信息区。
2. 补充说明承载问题背景；缺失时使用轻量空说明，不当作请求失败。
3. 话题以中性胶囊展示；保持可点击语义。
4. “写回答”作为当前内容区主操作使用主题色。
5. 回答数量与“默认／最新”排序构成列表头，排序控件不挤压计数。
6. 回答卡片包含作者、摘要与统计，以圆角中性底区分各条回答。
7. 左下关注胶囊、右下评论／更多胶囊独立悬浮，中间保留阅读空间。

宽屏问题页可以扩展信息区和回答列表，但不应让长段文字无限拉长。长文阅读建议采用居中限宽；问题页的限宽需要兼顾统计、排序、主按钮和回答摘要，通过长标题与长段落验证后确定，不能仅按屏幕宽度拉伸。

## 6. 沉浸光感与底栏

### 6.1 视觉使用范围

底栏和顶部按钮应表现为与内容有轻微距离的悬浮控件：圆润轮廓、柔和边缘、清晰前景，背景随下方内容变化。透明感不能以牺牲文字和图标可读性为代价。

| 区域 | 选择 | 注意事项 |
| --- | --- | --- |
| 根底部导航 | HDS 悬浮导航，统一材质与尺寸 | 宽屏保持紧凑居中；不扩大成横跨全屏的厚底板 |
| 详情操作胶囊 | 独立材质容器包裹相关动作 | 按内容实测宽高包裹，不把中间空白画成整条材质 |
| 顶栏按钮 | HDS 返回按钮或自定义圆形材质按钮 | 保留首屏与滚动态可读性，右侧动作不额外套大卡片 |
| 普通内容与设置分组 | 语义背景色、分割线或圆角表面 | 不普遍增加材质，不在每个列表项重复采样背景 |

根底栏高度为 64vp、侧边距参数为 16vp，底部按系统手势区高度避让。详情胶囊材质容器至少 48vp 高，随内容测量增高，圆角取高度的一半。两种控件不强制同高。

### 6.2 材质等级与兼容规则

沉浸光感使用系统提供的材质能力。设计需区分以下能力范围，避免承诺设备无法呈现的效果：

| 材质能力 | 用途与接口标识 | 设计边界 |
| --- | --- | --- |
| HDS 组件材质 | `hdsMaterial` / `systemMaterialEffect`，用于底栏、标题栏和材质画布 | API 23 起可用；最终效果取决于设备能力与组件兼容策略 |
| ArkUI 系统材质（API 26+） | `uiMaterial.ImmersiveMaterial` / `.systemMaterial(...)`，为圆形按钮、胶囊等控件应用系统材质 | API 26 起可用；不可用时采用普通模糊，必要时补充中性背景以保证可读性 |

`uiMaterial` 是系统提供的 API；应用负责选择样式并将材质应用到控件，不自行实现材质。**API 26+ 限制属于 ArkUI 的这条接入路径，不表示所有沉浸光感都要求 API 26。**

HDS 材质等级提供“自适应／精美／轻柔／流畅”四挡，以 **Select 下拉控件** 呈现。默认选中自适应；流畅仍属于材质效果，不标记为“关闭”。

| 情况 | 必须采用的策略 |
| --- | --- |
| 自适应 | 交给系统决定，不在界面虚构当前实际等级 |
| 精美／轻柔且设备支持 | 使用所选等级 |
| 精美／轻柔但不支持或查询失败 | 生效等级降级到流畅，保留用户保存的选择并给出兼容说明 |
| 流畅 | 优先减少材质开销；不解释成关闭材质 |

运行时 API 版本只判断接口能否调用，不代表设备一定支持预期材质效果。HDS 的 `materialLevel` 四挡与 ArkUI 的 `ImmersiveStyle` 厚薄样式是不同维度，不能直接对应，也不能宣称通过 `.systemMaterial(...)` 绘制的按钮会自动跟随 HDS 四挡。

材质降级后，控件的轮廓、尺寸、位置、操作与信息层级保持一致，只减少光效、透明或折射表现。若背景过于复杂，优先加强中性底色与文字对比，不以“更通透”为由降低可读性。不同设备可以有不同光效，但不能出现文字混叠、异常色块或布局跳动。

### 6.3 浮层与操作反馈

- 浮层按实际尺寸及底部安全区让位；最后一条内容和分页提示必须能滚到浮层上方。
- 胶囊中间的空白允许正文交互；装饰材质层不截获点击。
- 按下反馈使用现有组件状态效果；选中状态同时有图标、文字或形态差异，不只换色。
- 自动隐藏／显示必须遵循用户配置，按明确的滚动方向与阈值切换，不在滚动停止后抖动或持续闪现。
- 弹出键盘后输入区与提交操作保持可见，不让阅读胶囊覆盖输入框。
- 材质面积与层数保持克制；不要在同一控件上无条件叠加系统材质和模糊兜底。

## 7. 设置、表单与控件

设置条目按“组标题 → 主标题／必要说明 → 当前值或操作”的顺序组织。能在一行解释清楚的功能不增加重复说明；次级文字应说明结果或范围，而不是重复标题。

| 内容 | 控件选择 | 规则 |
| --- | --- | --- |
| 打开下一级 | 导航行 + 尾部箭头 | 整行点击，尾部值不压缩标题 |
| 二元偏好 | Switch / Checkbox | 当前状态清楚，选中颜色跟随主题 |
| 少量并列状态，如回答排序 | 分段选择控件 | 同组互斥选择，选中项明确；宽度容纳全部标签，大字时不溢出 |
| 多个离散选项，如材质等级 | Select | 显示当前选项，选择后即时反馈；不为展示全部选项强撑一行 |
| 连续量，如阅读字号、透明度 | 滑杆 | 同时展示数值或百分比；统一轨道、滑块及操作区尺寸 |
| 文本输入 | 输入框 + 标签／说明 + 明确提交 | 错误贴近字段，失败保留输入，键盘不遮挡操作 |
| 退出或清除 | 中性操作与必要确认 | 不与保存／发布共用高强调主按钮外观 |

卡片／分割线样式跟随全局外观偏好。卡片模式的设置分组使用 `surface_background` 与 16vp 圆角；分割线模式使用透明背景与零圆角，通过组标题和行间细线区分内容。切换样式只改变表面组织，不改变信息顺序与操作含义。

## 8. 宽屏、窄窗与大字体

布局以**实际容器 vp 宽度**判定；不要根据设备名称、物理分辨率或“是否平板”硬编码。分屏、窗口缩放与字体放大都可能让布局回退。

| 场景 | 布局规则 | 设计注意点 |
| --- | --- | --- |
| 信息流 | 600／840／1440vp 为两／三／四列候选起点；最多四列；还受最小卡宽、列间距、字体及用户列数偏好保护 | 同一设备可因窗口和字号变化采用不同列数 |
| 信息流卡宽 | 基础最小卡宽 280vp，列间距 14vp，外边距 12vp；字体放大提高最小卡宽 | 宁可减少列数，不挤压标题与摘要 |
| 设置双栏 | 容器至少 900vp，且容得下目录 280vp、详情 480vp 与间距；最小栏宽随字号放大 | 不满足时逐级导航；详情内容最大宽度 720vp |
| “我的”分组 | 至少 720vp 且每列能满足最小 320vp 时双列；整体最大宽度 1120vp | 资料与快捷区维持整体关系，不拆成零散小卡 |

信息流实际列数取“期望列数”与“空间可容纳列数”中的较小值，并限制在 1～4 列；跨过断点后仍须满足最小列宽。设置双栏的栏间距为 24vp，目录和详情的最小宽度同时乘以字体缩放系数，空间不足时回退逐级导航。

大字体优先增加行高、换行、减少列数或调整控件排列。顶栏等确需限制行数的区域仍须保证按钮可达、标题可理解；不得通过全页统一缩小字体来消除溢出。

## 9. 状态、文案与无障碍

页面必须覆盖正常内容以外的状态，并为可恢复的问题提供明确的下一步。

| 状态 | 展示与恢复规则 |
| --- | --- |
| 首次加载 | 有明确加载提示；顶栏和导航稳定，不先显示空数据再闪成加载中 |
| 已有内容刷新 | 保留当前内容和位置，局部显示刷新状态 |
| 空内容 | 说明具体为空的对象；有合理下一步才提供操作 |
| 网络失败 | 说明暂时无法加载并提供重试；保留已有内容与用户输入 |
| 未登录 | 说明需要登录的功能与登录入口，不混同网络错误 |
| 分页失败／到底 | 在列表尾部展示；不覆盖全部内容、不无限重复加载 |
| 提交中 | 防重复触发，明确进度；成功或失败有可理解反馈 |

- 加载、空态与错误面板使用统一组件，文字、间距和按钮层级遵循同一规则。
- 图标使用鸿蒙官方 Symbol，保持语义、尺寸和视觉重量一致；同一操作在不同页面使用相同图标。
- 所有纯图标按钮提供可被屏幕朗读的操作名称，如“返回”“分享问题”“更多操作”；装饰层不参与点击或焦点遍历。
- 按钮视觉尺寸与点击区域分别检查。圆按钮视觉直径为 40vp；建议在不造成热区重叠的前提下提供更宽裕的可点击范围。
- 检查屏幕朗读顺序、焦点可见性及大字状态。选中／禁用／错误不能只靠颜色区分。
- 文案简短、具体；不在普通界面展示 API 版本、状态广播键或内部材质实现名。

## 10. 交互一致性与动效

同类控件在不同页面保持相同的外观、状态和操作含义。导航、选择、提交与阅读各有明确反馈，用户不需要通过试错理解控件。

| 场景 | 交互要求 |
| --- | --- |
| 按下操作 | 立即给出轻量按下反馈；等待结果时显示忙碌状态，避免重复提交 |
| 改变选择 | 选中项的文字、图标或形态同步变化；相关设置即时生效，不要求重新进入页面 |
| 改变主题与样式 | 已打开页面保持一致；只改变视觉表现，不改变信息顺序和操作含义 |
| 返回与恢复 | 回到实际来源，保留合理的滚动位置、筛选条件与阅读上下文 |
| 窗口变化 | 列数和分栏变化后保留所选内容，避免跳回默认分类或丢失输入 |
| 不可用操作 | 显示清晰的禁用态或隐藏无关入口；需要解释时提供简短原因 |

动效用于解释状态变化和空间关系。顶栏标题切换、浮层显隐与布局过渡保持短促、连续，不遮挡内容、不抢夺阅读注意力。避免无意义的循环动画；在减少动态效果的场景下，仍须通过静态状态清楚表达结果。

视觉调整应保留功能语义。若需要改变导航结构、默认操作或信息优先级，应明确新的用户路径，不能仅以“统一外观”解释行为变化。

## 11. 设计验收标准

设计评审与界面还原均按以下体验结果判断。既检查静态画面，也检查滚动、选择、输入和页面切换后的表现。

| 维度 | 达标表现 |
| --- | --- |
| 视觉层级 | 标题、正文、辅助信息和主操作主次明确；颜色、字阶、留白与圆角一致 |
| 主题与样式 | 深浅色均清楚可读，强调控件跟随主题色；卡片与分割线模式保持相同信息结构 |
| 导航与遮挡 | 返回路径清楚，顶栏无重复标题；首尾内容、输入框和关键操作不被浮层或键盘遮挡 |
| 响应式布局 | 窄窗、宽窗、分屏和大字体下无重叠与截断；布局切换后保留用户上下文 |
| 状态与反馈 | 加载、空内容、错误、登录限制和提交状态可理解；用户知道操作结果与下一步 |
| 材质与可读性 | 悬浮层边界清晰，背景不干扰前景；材质降级后仍可阅读、识别和操作 |
| 无障碍 | 纯图标操作可被朗读，焦点顺序合理、点击区域可达，状态不只依赖颜色表达 |

存在例外时，说明适用场景及体验上的必要性，并确认其他页面不会因此产生矛盾的操作预期。

## 12. 规范维护

- 设计决策直接写成可执行规则，注明适用场景、尺寸、状态和兼容边界，不以“某页现在的样子”代替定义。
- 颜色、尺寸、控件结构或交互发生变化时，同步更新对应章节及必要示例。
- 新增例外时说明触发条件及用户体验原因；修复后删除失效的例外，避免临时处理变成永久规则。
- 设备测试、截图、构建结果和一次性排查过程放在变更记录中，不混入长期规范。
- 代码示例只用于消除视觉规则的歧义，保持短小；状态管理、组件语法、构建和排查步骤不纳入正文。
