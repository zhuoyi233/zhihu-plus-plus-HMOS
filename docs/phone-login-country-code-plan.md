# 手机号登录国家/地区码支持计划

调研日期：2026-10-27。状态：调研与实施计划；第 1~3 步已按本计划落地（见文末“实施记录”），
真实短信与设备联调仍未完成。

## 1. 结论与范围

建议将手机号登录的固定 `+86` 改为可搜索的国家/地区选择入口，第一版内置知乎官网登录页的 **182 个国家/地区条目、180 个不同拨号前缀**，默认中国 `+86`。采用 ArkUI 原生 `bindSheet + Search + List` 实现选择界面，号码处理独立于 UI，并让短信发送、图形验证码后重试和登录使用同一份规范化结果。

在此次核对的 HarmonyOS API 26 SDK（26.0.0.105）公开 ArkUI/HDS/API 声明与官方文档中，**未发现专用的电话国家码选择器**。这是本次公开能力检索的结论，不是对所有系统内部组件的断言。原生通用组件可以满足需求，无需引入跨平台选择器或地图依赖。

官网列表只能证明 Web 登录页提供这些选择，**不能证明本项目使用的 Android 登录接口对全部地区均可发送短信并完成登录**。国际号码协议联调是功能验收门槛，不能用“菜单已展示”替代“国际手机号登录成功”。本次未输入真实手机号、未发送短信、未完成登录。

## 2. 知乎官网实测

来源：[知乎官网登录页](https://www.zhihu.com/signin)，进入“验证码登录”，展开默认“中国 +86”下拉框，通过页面无障碍树读取完整选项（索引 0–181），并实际选择“日本 +81”确认字段切换。

- 完整清单见文末附录，保留官网名称、区号和顺序，不使用第三方全球国家库代替知乎白名单。
- 默认中国 `+86`；前 13 项依次为：中国、美国、日本、中国香港、中国澳门、中国台湾、马来西亚、澳大利亚、加拿大、英国、新加坡、德国、俄罗斯。此顺序是观察结果，不把它称为官方“热门地区”分组。
- **同码不同地区**：美国/加拿大均为 `+1`；俄罗斯/哈萨克斯坦均为 `+7`。数据与选中状态不能以区号作为唯一键。
- **四位前缀**：如巴哈马 `+1242`、关岛 `+1671`、牙买加 `+1876`。这些是官网展示的拨号前缀，不能按“国家呼叫码最多三位”截断；其中包含共享号码计划的地区前缀。
- 官网列表末尾是塞尔维亚共和国 `+381`、毛里塔尼亚 `+222`，并非全表严格按区号排序。未观察到列表内搜索输入框。
- 名称如“斯威士兰”“瓜地马拉”“多明尼加共和国”照录官网；以后可添加检索别名，但不能在无依据的情况下改变服务端支持范围或补充其他区号。

## 3. 鸿蒙原生能力选择

| 能力 | 核对结果 | 本项目取舍 |
| --- | --- | --- |
| 专用 CountryCodePicker / CountryPicker | 官方在线检索及本机 API 26 的公开 API、ArkUI 组件声明中未找到 | 自行组合原生组件 |
| TextPicker | 通用文本滚动选择器，数据由调用方传入，API 8 起支持 | 182 项滚轮查找效率低，不作为首选 |
| bindSheet + Search + List | 半模态弹层配合搜索与可滚动列表；SDK 声明中 bindSheet 从 API 10 起可用 | 推荐，沿用仓库现有弹层与主题体系 |
| Localization Kit 的 i18n.PhoneNumberFormat | SDK 声明中构造器、format、isValidNumber 从 API 8 起可用；支持 E164 格式 | 用作号码格式化适配层，不能当作知乎地区白名单 |
| Map Kit 的 sceneMap.selectDistrict | 原生行政区划选择页面，countryCode 是 ISO 3166-1 alpha-2（如 CN） | 不是电话拨号前缀选择器，不引入 |

## 5. 交互方案

1. 手机号输入行左侧显示可点击的“国家/地区 +区号”入口，默认“中国 +86”。窄屏可缩短名称，但辅助功能标签必须读出完整地区、区号及当前选中状态。
2. 点击打开“选择国家/地区”半模态弹层：顶部搜索、下方列表；每行左侧地区名称，右侧区号与选中标记。长列表限定可用高度，不使用 FIT_CONTENT 展开全部条目。适配平板、横屏、字体放大与键盘避让。
3. 搜索匹配中文名称、配置的别名、地区标识以及去除可选 `+` 的区号；空查询按官网原顺序显示。搜索 `1` 应保留多个匹配项，不能只返回美国；无结果显示明确空态。第一版不额外增加拼音库、国旗资源或字母索引。
4. 点选即生效并关闭；取消/返回不改变原选择。再次打开定位当前项；搜索内容每次打开清空。默认不根据定位、SIM 或系统地区自动替用户选择，也不申请相关权限。
5. 第一版仅保留当前登录页面生命周期内的地区选择，不保存手机号、验证码，不新增设置持久化或数据库迁移。
6. 切换到不同地区时保留输入文本并重新校验，清空短信码、图形验证码、已发码身份及旧提示；不得截短号码。即使 US 切到 CA 仍须失效旧验证码状态。选择同一项为 no-op。
7. 网络请求过程中禁用地区与号码编辑；倒计时中允许编辑但保留发送冷却，不让切换地区绕过 60 秒限制。登录必须匹配本次发送成功时保存的地区与完整号码。
8. 使用已有 `resolvedThemeColor`、`onThemeColor`、中性色和官方 Symbol；可访问区域至少满足现有触控规范。产品文案写“选择国家/地区”“手机号格式不正确”等，不将 Android 协议或 API 名称暴露到新增交互中。

## 6. 数据、号码与协议设计

### 6.1 白名单

在 `data/src/main/ets/network/PhoneLoginRegions.ets` 新增明确类型的数据模型（拟定路径）：`id`（稳定地区标识）、`displayName`、`dialPrefix`（无 + 的字符串）、`formatRegion`（号码格式化用地区标识）、`searchAliases`、`order`。多数地区的 id/formatRegion 可用 CN、US、CA 等；特殊地区逐项核对，不能假定所有条目都有标准 ISO 国家码或系统格式化器都支持。

数据由本附录生成后人工核对，随代码版本维护。182 项完整性、180 个不同前缀、同码地区及四位前缀均纳入测试。白名单离线可用；不在登录时请求全球国家库，也不动态抓取官网脚本。

### 6.2 统一号码策略

新增 `PhoneLoginNumberPolicy.ets`（拟定路径，同上目录），输出显式 interface，例如规范化后的地区 id、`username` 和用户可理解的错误。UI 按钮启用、短信请求和登录都调用同一策略，避免 UI 放行但网络层仍拒绝。

- 中国大陆保留原有 `1` 开头 11 位规则，以及现有 +86/13 位 86 前缀输入兼容性。
- 其他地区不统一限制为 11 位。允许空格、连字符、括号等常见号码展示分隔符；其他非法字符报错，不能简单删掉任意非数字后发送。可统一全角数字；不支持分机号。
- 原始输入保留足够长度（例如 32 字符），超出展示上限明确提示，不静默 `substring`。最终发送值必须是 `+` 与数字，数字总长度最多 15；这是结构边界，不代表号码已分配或一定可收短信。
- 无 `+` 的输入按所选地区的本地号码解释；用 `i18n.PhoneNumberFormat(region, { type: 'E164' })` 处理地区特有国内拨号前缀，不能全球统一去掉开头的 `0`。日本/英国国内前导 0、意大利需保留的 0 应有单独用例。
- 对官网 `+1242` 等复合前缀，先区分“7 位本地号码”与“包含地区前缀的号码”，确保生成结果只包含一次 1242；以地区映射及明确规则处理，不重复拼接。格式化结果仍须符合所选白名单前缀。
- 粘贴完整 `+` 号码时，只接受与当前所选地区匹配的结果；不匹配则提示切换国家/地区，不默默改区号或重复添加前缀。共享 +1/+7 时保留用户选择，不能仅凭短前缀擅自推断具体地区；更长的白名单前缀优先识别。
- 不自动猜测所有无 `+` 输入中的国家码，不默认把 `00` 当作所有地区通用国际前缀；提示使用 `+` 格式。
- `isValidNumber` 可用于格式提示，但系统号码段资料可能滞后，不宜把其 false 结果作为唯一硬拒绝条件。硬限制为白名单、合法字符、明确的地区结构规则与规范化结果。格式化失败/特殊地区不支持时不猜测删号，提供明确国际格式输入路径；保留原输入。降级也必须校验所选前缀和长度。

原生格式化适配器与纯策略分离：宿主测试注入假实现；API 23 模拟器验证真实格式化结果，避免宿主空桩让用例假通过。特殊地区的 formatRegion 映射和上述号码示例必须在实现阶段逐项确定并测试。

### 6.3 客户端与状态一致性

- 为 `requestDigits(phoneNumber, regionId = 'CN')`、`signIn(phoneNumber, digits, regionId = 'CN')` 增加显式地区参数并保留默认值，旧调用仍使用大陆行为；内部在网络请求前生成不可变的号码快照。
- 两个接口继续传 `username=+前缀号码`，经现有 formUrlEncode 编码（`+` 必须是 `%2B`）后再加密。**不凭官网 UI 猜测新增 country_code 字段或替换 Web 登录接口**。国际 username 能否被 Android 端接受，待联调核实。
- 验证码成功发送时记录 `sentIdentity = regionId + username`；登录只使用匹配的号码快照。图形验证码挑战也绑定本次身份，切换地区/号码使其失效。
- 将发码/验证/登录状态提取为可测试流程（可新增 `PhoneLoginFlow.ets`），统一忙状态管理。修复图形验证码通过后重复进入忙状态守卫的问题。
- 请求使用 generation/token 忽略过期结果；页面退出后迟到回调不得修改状态或触发登录成功回调。刷新图形验证码也纳入同一规则。
- 短信冷却维持至少当前 60 秒，按到期时间计算；地区或号码变更不清零。服务端限流仍由接口错误反馈处理。
- 登录成功继续使用现有 `onCookiesCaptured` 与 LoginController 会话验证通道。服务端拒绝时提供可操作提示与已有网页登录入口，不声称所有国际号码已支持。

## 7. 实施顺序与改动边界

1. **数据与纯逻辑**：固化附录白名单、补地区映射、实现号码策略与格式化适配器；由 `data/Index.ets` 导出。先通过重复区号、复合前缀和国内拨号前缀测试。
2. **协议与状态流**：扩展客户端地区参数、记录发送身份、增加可注入的请求/时钟边界，修复图形验证码后发码并覆盖竞态。只改号码相关行为，保留现有签名与加密实现。
3. **原生 UI**：新增 `entry/src/main/ets/pages/PhoneCountryCodeSheet.ets`（拟定），接入 PhoneLoginPage；沿用现有弹层关闭、主题、生命周期和软键盘处理方式。
4. **联调与验证**：先离线/模拟接口验证，再在用户提供测试号码并明确授权后进行少量真实短信及登录联调。无法取得国际测试号码时记录未验证范围，不把该项标为完成。

预计改动范围：上述新增文件，PhoneLoginPage、ZhihuPhoneLoginClient、data 导出、相应 Hypium 测试与 `entry/src/test/List.test.ets` 注册。不涉及扫码登录改造、reader 模块、签名配置、版本号、数据库迁移或发布流程。

### 与计划的差异与取舍

- 号码长度只做结构校验（E.164 ≤15 位、地区码后至少 3 位、本地号码至少 4 位），
  **不使用 `isValidNumber` 作为硬拒绝条件**（该接口仅确认可用，代码中未调用），地区特有位数与号码段
  由 i18n 格式化结果与服务端判定，避免系统号码段滞后时误伤真实用户。
- 非大陆地区的“已带地区码”输入先剥离一次地区码再交给格式化端口，剥离与重新拼接对巴哈马 `+1242`、
  巴西 DDD 55 这类“本地号恰好以地区码开头”的情况都不改变最终号码，因此能同时满足
  “复合前缀不重复拼接”和“不猜测删号”。
- 格式化端口不支持某地区时降级为“必须输入 `+` 开头的完整号码”，仍校验前缀与长度，不静默删号。
- 选择弹层挂在手机号登录卡片的根节点上（`bindSheet`），沿用仓库既有弹层关闭、主题与生命周期写法；
  未新增拼音库、国旗资源或字母索引。
