# 设置搜索修复与设置项动画定位计划

日期：2026-10-29  
状态：待实施，仅产出计划文档。  
源码核对基线：`c9bf9019`；本次未修改业务代码，未运行构建、Hypium 或设备回归。

## 1. 目标与完成标准

修复用户反馈的“设置页面搜索无法使用”，让搜索结果能直接带用户找到具体设置项。完整体验为：**输入关键词 → 展示具体结果及所属路径 → 点击 → 设置详情切换动画 → 平滑滚动到目标 → 对应卡片闪烁两次 → 恢复原样**。

- 搜索随输入更新，支持清空、空结果、中文输入、英文大小写及常用别名；不能只搜到一个笼统分类后让用户继续寻找。
- 具体结果具有稳定的设置项标识、所属页面、滚动锚点和提醒卡片标识；同一页面里的不同结果能落到不同位置。
- 单栏在目录与详情间切换；双栏保留左侧搜索，在右侧切换与定位。保留当前设置内部导航和父级返回规则。
- 页面切换与滚动均有可感知动画；已在目标页面时不重复切页，已处于合适位置时不制造无意义滚动，直接执行提醒。
- 卡片提醒严格为“亮起—恢复—亮起—恢复”两个完整周期，仅作用于目标所在卡片。
- 搜索定位不改变设置值，不自动打开外部链接、确认弹窗或执行清理、退出、播放停止等操作。
- 编译目标保持 API 26，最低兼容 HarmonyOS 6.1.0（API 23）；覆盖深浅主题、卡片／分割线样式及大字体。

### 2.2 尚待复现的问题

“搜索无法使用”的设备端根因尚未确认。本计划已确认**细项索引及点击后的定位链路缺失**，但不能据此宣称输入不响应、结果不刷新或点击失效的原因已经查明。

实施第一步在 `ZhihuPlus_API23`（`127.0.0.1:5555`）逐层记录：

1. 搜索框能否获得焦点，中文输入及删除是否触发 `onChange`，`searchQuery` 是否变化。
2. 查询变化后，`hasQuery()`、结果集合及结果区域是否同步刷新；清空按钮是否及时出现。
3. 结果是否被原目录滚动位置、软键盘或覆盖标题栏遮挡；结果行能否收到点击。
4. 点击后 `openEntry()`、`paneForEntry()`、`selectedPane` 与实际内容是否一致。
5. 对照窄窗／宽窗、首次进入／返回后、登录态和开发者模式，定位失效的具体环节。

仅在临时开发诊断中记录查询长度、结果数、entry ID、请求序号与阶段，不记录 Cookie 或敏感表单内容。修复记录必须附实际复现步骤；不得凭 Builder 状态传播的既有风险直接断言本次根因。

## 3. 搜索与索引方案

### 3.1 从分类索引扩展为设置项索引

保留既有分类入口与 ID，为可独立定位的设置增加细项。查询命中具体标题时，具体项优先于分类结果；分类结果明确显示为分类入口，目标为该分类首个有效设置卡片。

建议提取 `SettingsSearchTarget.ets` 作为中立类型定义，承载条目 ID、pane ID、锚点 ID 和卡片 ID，避免当前导航模块依赖搜索索引后，又因索引引用导航类型形成循环依赖。既有类型可从原入口重新导出以减少迁移成本。

每个条目至少包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定且唯一的搜索结果标识，不使用显示文案或数组下标 |
| `title`、`path`、`keywords` | 实际设置名称、完整层级路径与别名 |
| `targetKind` | 内部设置项、分类入口或外部导航入口 |
| `paneId`、`anchorId`、`highlightGroupId` | 目标详情、精确滚动位置和提醒卡片；内部细项必须全部具备 |
| `visibility`／可用性条件 | 复用登录、开发者模式门禁，并处理动态依赖 |
| `fallbackAnchorId` | 条件隐藏时定位其前置开关；不存在合理落点则隐藏结果 |

第一阶段先完成下列代表项，验证链路后按页面清点全部可见设置；下表不是最终覆盖上限。实施时补一份“可见项—索引—锚点—卡片”清单，确保没有可搜索却无法落地的细项。

| 查询示例 | 目标页面与设置项 | 现有控件依据／计划补充 |
| --- | --- | --- |
| 字号、字体大小 | 外观与阅读体验 → 字号 | `fontSizeSetting()`；在整行增加独立锚点，提醒阅读分组卡片 |
| 行高、行间距 | 外观与阅读体验 → 行高 | `appearance_line_height`；锚点放在设置行而非仅 Slider |
| 段间距 | 外观与阅读体验 → 段间距 | `appearance_block_spacing` |
| 主题色、强调色 | 外观与阅读体验 → 主题颜色页 | 保留 `THEME_COLOR` 子页路径，定位实际选色区域 |
| 语速、朗读速度 | 朗读与播放 → 语速 | `reading_speed`，等待 `loaded` 和布局就绪 |
| 音调、音色 | 朗读与播放 → 对应语音项 | `reading_pitch`、`reading_voice_select` 分别对应独立锚点 |
| 广告、盐选 | 推荐系统与内容过滤 → 对应过滤开关 | `filter_zhihu_ad`、`filter_paid` |
| 主题屏蔽阈值 | 推荐系统与内容过滤 → 主题屏蔽阈值 | `filter_topic_threshold`；依赖关闭时定位 `filter_topic_enabled` 并提示需先开启 |
| 内容屏蔽、屏蔽记录 | 对应内部子页 | 保留 `FILTER → 子页` 返回层级，补规则分类／管理区域锚点 |
| GitHub、AGPL、开源许可 | 关于应用 → 对应行 | `open_project_home`、`open_project_license`、`open_open_source_licenses`；只定位，不自动执行行操作 |
| Cookie | 开发者选项 → 手动 Cookie 区域 | `developer_cookie_input` 所在卡片；开发者模式关闭时隐藏 |

通知、系统与更新、身份管理、外观其余项目及开发者页其余入口也纳入清点。只索引功能名称，不将账号列表、Cookie 值、屏蔽记录正文等运行数据加入设置索引。工具栏菜单中的导入／导出等项目应明确标注“更多菜单”，定位真实入口；不能伪造不存在的正文卡片。登录属于外部路由入口，保留既有跳转，结果明确标注“登录入口”，不套用不存在的设置卡片定位。

### 3.2 匹配、排序和刷新

- 输入与索引文本统一去除首尾空白、英文小写化；连续空白合并，多词查询拆词后要求各词均能在该条目字段中命中。
- 常用别名显式维护，例如“字体大小／字号”“行间距／行高”“朗读速度／语速”，本次不引入联网搜索或额外拼音库。
- 排序采用固定优先级：标题完全匹配 → 标题包含 → 别名／关键词 → 路径；同级按索引顺序稳定排序，ID 去重。
- 基于查询和可见性状态显式维护结果集合，在输入、登录态、开发者模式变化时统一重算；避免多个 Builder 内反复计算产生不一致的快照。是否必须改为此方式以首阶段复现结论为准。
- 空白查询恢复目录；无匹配时显示现有空结果提示及清空操作。修改查询后将结果列表回到起始位置；从详情返回则保留查询与结果列表原位置。
- 点击时再次验证可见性和可用性，不能让旧结果绕过已关闭的开发者模式或失效的登录态。

## 4. 点击后的定位协议

### 4.1 单次请求与生命周期

区分目录 `openEntry()` 与搜索激活入口。搜索激活创建强类型请求，至少包含 `sessionId`、递增 `requestId`、`entryId`、`paneId`、`anchorId`、`highlightGroupId`。同一结果再次点击也生成新请求，保证可重复定位。

跨页面信号遵循仓库约束：使用 AppStorage 广播与 `@StorageProp` + `@Watch`，不依赖 `@Builder` 按值参数更新或 `@Provide`／`@Consume`。建议约定请求快照和最后更新的 tick；接收端由 tick 触发后读取完整快照，避免读取到部分写入的数据。请求类型使用明确 interface，必要时用具体 class 承载运行时对象，符合 ArkTS 约束。

目标页首次挂载主动检查待处理请求，以接住广播早于挂载的情况；已挂载页监听 tick。只允许当前设置会话、当前可见 pane 且 `embedded` 的实例消费请求；独立根路由实例不能误响应。确认消息携带相同 session/request ID，宿主与目标页都忽略过期确认。

```text
结果点击 → 校验 → 收起键盘并移出搜索焦点 → 发布请求 → 切换目标 pane
    → 等待切换完成 + 目标内容加载 + 有效布局
    → 计算位置 → 动画滚动 → 确认到达 → 卡片亮/灭两次 → 完成

任意阶段：新请求／用户返回／离页／可见性失效 → 取消旧请求并清理提醒
```

建议状态为 `pending → switching → waitingLayout → scrolling → highlighting → completed`，以及 `cancelled`／`failed` 终态。同页请求跳过 `switching`，零距离滚动跳过 `scrolling`。动画完成回调、布局回调和超时都必须检查请求 ID，避免旧回调修改新页面。

### 4.2 返回与连续操作

- 普通目录进入不触发搜索提醒；搜索进入不新建额外根导航记录。
- 沿用 `paneParent()`、`hasInternalBack()`：子页先回父页，单栏分类根回搜索目录；双栏分类根的系统返回仍按既有约定退出设置。
- 双栏搜索词和结果位置保留；清空左侧搜索只恢复目录，不重置右侧。
- 连点 A→B 时只完成最新 B；取消 A 的待执行滚动、动画回调和定时器，复位 A 卡片。再次点 A 可以重新完整播放两次提醒。
- 用户主动拖动详情时取消自动定位，不与手势争抢位置；普通滚动结束不得误触发新一轮闪烁。
- 旋转或跨宽度断点时重新测量尚未完成的请求；已完成的请求不因重新布局而再次闪烁。
- 离页、会话销毁、开发者模式关闭或认证失效时清理请求、锚点注册和动画资源，不在下次进入时重放陈旧任务。

## 5. 切换、滚动与闪烁动画

以下数值为实施初始参数，最终在 API 23 模拟器及目标设备上校准；两个闪烁周期为固定验收要求。

### 5.1 页面切换

- 单栏：目录进入详情时采用约 220ms 的轻量横向位移（约 16–24vp）和淡入；内部返回采用对应反向过渡。
- 双栏：仅右侧内容采用约 180–220ms 淡入及轻微位移，左侧搜索保持稳定。
- 使用项目既有 `getUIContext().animateTo()` 使用方式作为实现参考；动画状态与业务选中状态分离，切换期间旧内容不接收点击。
- 不依赖仅修改 `Visibility.None` 自动产生转场。实施时明确选择保留旧内容到退场结束或仅新内容入场，避免双重布局、重叠可点击区域和跳帧。
- 滚动必须等目标切换完成、搜索焦点释放及键盘引起的视口变化稳定后开始；同页点击不重新播放切换动画。

### 5.2 精确滚动

每个详情页持有绑定其真实滚动容器的 Scroller，并注册“设置行锚点—所属卡片”关系。不在宿主外层新增包裹所有页面的 Scroll，避免双层滚动。

- 锚点覆盖设置整行，卡片标识对应其实际分组容器；保留现有控件测试 ID，并增加独立定位 ID。
- 在布局就绪后测量锚点与滚动视口，使用一致坐标系与 vp 单位。概念计算为 `目标偏移 = 当前滚动偏移 + 锚点视口位置 - 希望的视口位置`，再钳制到合法滚动范围。
- 希望位置为悬浮标题栏可见下沿再留约 12–16vp；沿用 `floatingTitleBarOffset()` 的语义，明确 `contentStartOffset` 是否已包含这段让位，避免重复扣减。
- 不硬编码第几行、固定行高或历史绝对坐标；大字体、状态提示、异步加载及窗口宽度变化都会改变布局。
- 普通距离建议 280–400ms，较长距离上限约 500ms，使用缓出滚动；首尾边界只要求目标尽量完整可见，超高设置行优先展示标题与主控件。
- 滚动完成后重新测量可见性和偏差；必要时进行一次有限纠偏，再开始闪烁。零距离或边界钳制无需等待不会到来的滚动回调。
- 区域变化回调只作为布局就绪证据之一，不能假定每次滚动都会触发。优先在实际滚动结束事件后确认落点，不用固定延迟猜测滚动结束。
- 异步页等待业务加载完成与目标布局完成两个条件。目标未出现时只进行有限重试，建议总等待上限 3 秒；失败后保留目标页并提示“暂时无法定位，请稍后重试”，不得闪烁错误卡片或无限轮询。
- 条件隐藏项使用声明的前置开关落点，提示“需先开启……后设置”；不自动修改开关。无法提供有效落点的条目从结果中隐藏。

### 5.3 对应卡片闪烁两次

由可复用的提醒容器或修饰能力管理卡片高亮强度，动画只改变主题色淡背景／描边的强度，不改变卡片尺寸、边距、文本透明度或控件值。

| 阶段 | 建议时长 | 视觉状态 |
| --- | --- | --- |
| 第一次亮起 | 160ms | 淡主题色背景／描边从 0 到目标强度 |
| 第一次恢复 | 200ms | 强度回到 0 |
| 间隔 | 100ms | 保持原样 |
| 第二次亮起 | 160ms | 同第一次 |
| 第二次恢复 | 200ms | 回到 0，标记完成 |

- 总计约 820ms；通过有限阶段链控制，不使用无限循环动画或永久 `setInterval`。
- 强调色只读取 `resolvedThemeColor`，深浅色分别校准透明度，避免默认系统蓝或直接使用 seed。
- 卡片模式提醒目标所属分组卡片；分割线模式在对应逻辑分组使用临时淡背景，结束后恢复原分割线外观。若分组超过一屏，不要求显示整组，但目标设置行必须可见。
- 提醒层不阻断控件交互，不改变原语义或无障碍节点；卡片内有多项时，精确滚动落点仍必须对应命中的那一行。
- 高亮在滚动落定后才开始；已取消、已消费或过期的请求不得重复执行。
- 若设备启用减少动态效果，计划退化为无位移切换、即时定位和短暂静态描边提示；该例外需在测试记录中明确，普通模式仍严格闪烁两次。系统偏好读取方式在实现前核实 API 23 支持。

## 8. 验证计划

### 8.1 自动化验证

- 匹配：空白、大小写、别名、多词、同名不同路径、排序、ID 唯一与去重；更新原先只期待分类命中的断言。
- 可见性：登录态切换、开发者模式关闭、点击过期结果、条件隐藏项与前置开关回退。
- 导航：每个内部细项映射到存在的 pane 与锚点声明；保持主题颜色／规则／记录父级关系及外部登录入口行为。
- 请求：同项二次点击、新请求覆盖旧请求、广播先于挂载、离页取消、超时、无滚动距离、重复滚动结束回调只消费一次。
- 提醒：两个完整周期后复位；取消不启动后续周期；布局变化不重放已完成请求。使用可控事件／时钟验证状态，不用真实等待拼凑测试，也不为固定颜色值写镜像测试。
- 坐标纯逻辑：视口顶部遮挡、底部钳制、超高行、不同字体尺寸下的目标计算；设备验证负责证明实际测量与动画正确。

| --- | --- |

| 窄窗搜索“行高” | 切换到外观页，平滑滚动到行高行，阅读卡片闪烁恰好两次 |

| 横竖屏／宽窄断点变化 | 未完成任务重测位置，已完成提醒不重播，返回规则保留 |
