# 收藏夹二级页：主页信息流卡片复刻设计

日期：2026-11-07。状态：已实施（含历史记录页同套适配与在线历史封面图源接入，见仓库提交）。

源码基线：`1feee083`。配套文档：[实施计划](./collection-content-card-plan.md)。

## 1. 目标与页面范围

进入某个收藏夹后，在 `CollectionContentPage` 中浏览的**单条收藏内容**，采用与 `HomeFeedPage` 单条信息流完全相同的排版、字体、图文结构、间距、表面和更多按钮。两页使用同一套卡片呈现组件，以后修改主页卡片时同步生效。

接入外观设置中已有的“列表样式：卡片／分割线”，跟随全局偏好即时更新。收藏内容不另设样式开关。

本次设计覆盖回答、文章、问题、想法四类收藏内容。收藏夹目录页 `CollectionPage`、二级页顶栏与导航结构、收藏夹管理、收藏／取消收藏流程保持现有职责；此方案不重设计这些区域。宽屏继续使用收藏内容页已有的居中限宽和自适应瀑布流。

“完全复刻”的判定条件是：**相同卡宽、相同字体缩放、相同展示字段与全局样式下，主页和收藏内容卡片的可见区域布局一致**。内容来源特有的文案与菜单动作由页面提供，不补造推荐理由，也不把想法当成回答。

## 2. 当前实现与差距

以下为本次静态核对结果。

| 区域 | 主页实际实现 | 收藏内容页实际实现 | 设计要求 |
| --- | --- | --- | --- |
| 信息顺序 | 标题 → 作者 → 图文摘要／推荐语 → 统计与更多 | 类型与作者 → 标题 → 摘要 → 统计 | 采用主页顺序，类型只在页脚出现 |
| 标题 | 20fp、Medium、完整换行 | 20fp、Medium、完整换行 | 保留完整标题，不新增行数上限 |
| 作者 | 20vp 头像（有地址时）＋14fp 姓名 | 12fp 姓名，与类型并排 | 作者独立成行，尺寸与主页一致 |
| 摘要 | 16fp、`secondary_text`，行数随图片及列数变化 | 16fp、`secondary_text`，固定最多三行 | 复用主页动态行数规则 |
| 缩略图 | 左侧大图，右侧摘要 | 无 | 接入共享 `FeedThumbnail` 与现有缩略图开关 |
| 页脚 | 14fp、最多两行，右侧更多按钮 | 12fp 纯文本 | 复刻同排结构及更多按钮 |
| 表面 | `feedCardStyle` 决定圆角表面或底部分割线 | 固定 `card_background` 与圆角 | 接入已有全局偏好 |
| 条目间距 | 单列分割线 0；卡片或多列 14vp | sections 间距固定 10vp | 按主页规则处理内容 section |

主页的排版实际位于 `HomeFeedPage.feedCard()`、`feedCardContent()`、`feedCardMenuButton()`，不是 `components/FeedContentSummary.ets`。后者当前使用 24vp 头像、不同摘要颜色及间距，不能直接作为完整复刻的替代品。

收藏模型 `CollectionContentItem` 目前只有作者姓名，没有头像和封面字段。此差距需要在实施时补齐数据链路，不能只加入空图片占位后宣布完成。

## 3. 单条内容结构

### 3.1 有图内容

下图只表达结构；实际尺寸以第 4、5 节为准。`⊙` 表示主页现有 `ellipsis_circle` 更多图标。

```text
┌──────────────────────────────────────┐
│ 完整标题：允许自然换行                 │
│ ● 作者姓名                           │
│ ┌─────────────┐  摘要第一行           │
│ │             │  摘要第二行           │
│ │ 左侧缩略图  │  ……                  │
│ │             │                      │
│ └─────────────┘                      │
│ 回答 · 128 赞同 · 16 评论          ⊙ │
└──────────────────────────────────────┘
```

标题、作者位于图文区上方并占用正常内容宽。图片不是横跨卡片顶部的封面，不移到右侧。摘要列在图文区内占剩余宽度，并与图片顶部对齐。

### 3.2 无图内容

```text
完整标题：允许自然换行
● 作者姓名
摘要占满内容宽度，超过允许行数后省略……
文章 · 128 赞同 · 16 评论              ⊙
```

没有封面或关闭“显示信息流缩略图”时，图片区域整体移除，文字占满宽度。作者不存在时移除作者行，不添加“知乎用户”或额外空行。没有头像但有姓名时只展示姓名，与主页实际行为一致。

收藏来源没有推荐理由或推荐来源行，不显示“推荐内容”“手机版推荐”等兜底文案。共享组件支持主页继续呈现真实推荐语，但收藏适配器将该字段留空。

### 3.3 各类型页脚

| 类型 | 标题与正文 | 页脚 |
| --- | --- | --- |
| 回答 | 问题标题＋回答摘要 | `回答 · N 赞同 · N 评论` |
| 文章 | 文章标题＋文章摘要 | `文章 · N 赞同 · N 评论` |
| 问题 | 问题标题＋问题补充说明摘要 | `问题 · N 回答 · N 评论` |
| 想法 | 保留当前标题“想法”＋正文摘要 | `想法 · N 赞 · N 评论` |

页脚先沿用收藏模型中真实的 `details` 语义，排版复刻主页。当前问题的 `voteupCount` 字段实际承载回答数，不能送入主页的通用赞同文案；想法的赞也不改写为赞同。

## 4. 共享排版规格

尺寸直接来自当前主页源码及 `entry/src/main/resources/base/element/float.json`。实施时引用现有资源，避免复制一套常量。

| 元素 | 规格 |
| --- | --- |
| 总体 | 内容垂直排列、左对齐；卡高随标题、摘要及图片自然增长 |
| 主区域纵向间距 | `spacing_xsmall`，4vp |
| 标题 | `heading_font_size`，20fp；Medium；`primary_text`；宽度 100%；不截断、不限行 |
| 作者行 | 元素间距 4vp，垂直居中；作者名 14fp、`secondary_text`、单行省略 |
| 作者头像 | 有有效字段时显示；20×20vp，圆角 10vp；缺失时不保留头像槽 |
| 图文区域 | 水平排列，间距 `spacing_small` 10vp，顶部对齐 |
| 缩略图 | 图文区宽度的 42%，`aspectRatio(1)`、`maxHeight: 150vp`；圆角 10vp；直接复用主页约束与 `FeedThumbnail` 裁切方式 |
| 摘要列 | `layoutWeight(1)` 占剩余宽；内部间距 4vp |
| 摘要 | `body_font_size`，16fp；`secondary_text`；超行省略；空白摘要不绘制 Text |
| 页脚行 | 水平间距 10vp，垂直居中；文字占剩余宽 |
| 页脚文字 | `secondary_font_size`，14fp；`secondary_text`；最多两行，超行省略 |
| 更多按钮 | 32×32vp，padding 0，透明底；`sys.symbol.ellipsis_circle` 18fp，`secondary_text` |
| 按压反馈 | 与主页相同的普通 Button 状态反馈；更多按钮有独立点击语义 |

摘要最大行数与主页共用计算：

| 是否实际显示缩略图 | 当前最终列数 | 最大摘要行数 |
| --- | --- | --- |
| 否 | 1 | 3 |
| 否 | 2～4 | 2 |
| 是 | 1～2 | 6 |
| 是 | 3～4 | 4 |

图片加载失败时，沿用 `FeedThumbnail` 的中性画布，占用尺寸不变；图片开关关闭时按无图行数计算。摘要为空但有有效封面时仍允许展示封面。两者都为空时，图文区不增加可见的占位高度；主页和收藏共用相同处理。

## 5. 卡片／分割线两种外观

两种外观采用相同的信息顺序和内部结构。仅由 `feedCardStyle === 'card'` 决定是否使用卡片表面，多列不强制改成卡片。

| 项目 | 卡片 | 分割线 |
| --- | --- | --- |
| 条目背景 | `surface_background` | 透明，透出 `page_background` |
| 圆角 | `card_radius`，16vp | 0 |
| 内边距 | 四边 `card_padding`，18vp | 左右 8vp，上下 18vp |
| 底部分隔 | 无 | 1vp，`divider_color`，沿条目外框宽度绘制 |
| 单列内容间距 | 14vp | 0 |
| 多列内容行／列间距 | 14vp | 14vp |
| 阴影、材质、额外描边 | 均不新增 | 均不新增 |

卡片圆角必须同时写入 `borderRadius` 和 `border.radius`，避免 `.border()` 将背景圆角重置成直角。

窄窗两种外观结构示意：

```text
卡片                                 分割线
页面左右各 12vp                       页面左右各 12vp
╭────────────────────╮               标题（条目内再缩进 8vp）
│ 四边 18vp 内边距   │               作者
│ 标题／作者／摘要   │               摘要
│ 页脚           ⊙ │               页脚                ⊙
╰────────────────────╯               ──────────────────────
        14vp 间距                     下一条（无额外行间距）
╭────────────────────╮
│ 下一条             │
╰────────────────────╯
```

窄窗分割线模式的文字起点距页面边缘为 `12 + 8 = 20vp`。卡片模式的文字起点为页面外边距加卡内 18vp。宽窗外边距按收藏页现有居中规则增长；相同卡宽时，卡片内部仍与主页一致。

## 6. 设置、交互与状态

### 6.1 全局设置

- 复用已持久化的 `feedCardStyle`（`card`／`divider`），缺省为 `divider`；不新增存储键。
- 复用 `showFeedThumbnail`，同时控制主页与收藏内容缩略图的显示。
- 样式和缩略图偏好通过 AppStorage 与 `@StorageProp` 传播。已挂载、缓存后重显的页面都应更新，不重新拉取收藏接口、不清空已有条目、不主动回顶。
- “列表样式”的说明文案补充收藏内容范围，例如：“应用于信息流、收藏内容、‘我的’与设置列表；卡片使用圆角表面，分割线使用细线分隔条目。”

### 6.2 点击与更多

点击卡片主体继续使用收藏页当前的按类型导航：回答→回答页、文章→文章页、问题→问题页、想法→想法页。此次排版统一不迁移主页的推荐曝光上报、质量过滤或回答阅读模式解析逻辑。

更多按钮的位置、尺寸、图标与主页一致，点击只展开菜单，不打开内容。收藏页菜单本期提供**“外观设置”**，复用现有外观设置路由；返回后应用最新样式。菜单内容属于页面上下文，不复制主页的屏蔽用户／提问者／话题动作，也不新增取消收藏或删除能力。按钮必须可用，不能只留一个装饰图标。

### 6.3 页面状态

保留现有首次加载、空收藏夹、登录要求、整页错误、已有内容时的错误横幅及分页入口。错误横幅和加载尾独立占通栏 section，不按内容卡片分列，也不为它们添加收藏内容页脚和更多按钮。

继续使用现有 `floatingTitleBarOffset()` 与滚动注册机制，首尾卡片及加载入口可达。当前 `header()` Builder 虽已定义，但没有在页面构建树中调用；本方案不因此新增收藏夹简介头卡或重复标题。

## 7. 数据缺失与宽屏边界

作者头像、封面仅使用收藏列表响应中真实存在、已核验含义的字段。实施前用脱敏响应样本确认各内容类型的字段位置，补入可选模型字段；缺失字段沿用上述无头像／无图布局，不额外逐条请求详情。没有真实样本证明的头像与封面提取不能列为已完成。

继续使用 `resolveWideColumnSpec()`：内容最大宽 1120vp、按实际容器宽度与字号求列数。将当前 sections 的 10vp 内容间距改为与规格一致的 14vp，使列宽计算与真实列间距一致。保留现有列数策略，本期不额外接入“信息流列数”偏好；单个卡片复刻不要求整页列数与主页完全相同。

大字体时由现有最小卡宽保护减少列数，卡高自然增长。长作者名、长页脚不能挤出更多按钮；完整标题不设固定高度。图片失败、样式变化及数据分页不能造成错误跳转或内容身份错位。

## 8. 设计验收

1. 使用同一份展示数据、相同卡宽、相同字体缩放，对照主页与收藏页：标题、作者、图文、页脚、更多按钮的位置和尺寸一致。
2. 卡片／分割线 × 有图／无图 × 单列／多列均覆盖，摘要行数符合表格，标题完整展示。
3. 深浅主题均使用现有语义颜色；卡片底色与主页同为 `surface_background`，不继续使用收藏页旧的 `card_background`。
4. 问题显示回答数、想法显示赞；不出现重复的类型头行或虚构的推荐来源。
5. 设置变更后页面即时更新，已有内容和分页游标保留，当前阅读条目仍在可视范围；更多按钮不会误触内容导航。
6. 缺头像、缺作者、缺摘要、图片失败、长标题、长作者名和大字体状态均可读，屏幕朗读能识别“打开回答／文章／问题／想法”和“更多选项”。

本次完成源码静态核对与设计定义，尚未实现卡片组件、数据字段或设置接入，也未执行设备视觉验收、Hypium 或构建。
